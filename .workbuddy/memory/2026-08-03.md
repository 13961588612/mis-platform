## KB 交付收尾：T-D 二次改造 + QA 报告五轮更正（2026-08-03 晚）

### T-D 最终形态：手写 JPQL 被派生查询取代（全后端 `@Query` 归零）
主理人提议、工程师采纳：`KbQaFeedbackRepository` 的 `findBySessionIdForUpdate`（`@Lock`+`@Query`+`@Param`）→ **`findWithLockBySessionId`（`@Lock(PESSIMISTIC_WRITE)` + Spring Data 派生查询）**。

- **派生查询命名规则**：`find` 与 `By` 之间的内容是**描述性词汇、被忽略**（除 `Distinct`/`First`/`Top` 等结果限定词），故 `findWithLockBySessionId` ≡ `findBySessionId` 的查询语义，`@Lock` 照常生效。可用来消灭「只为挂 `@Lock` 而写的 JPQL」。
- 核验：`grep '@Query' backend/mis-kb/src/main` → 0；`backend/mis-admin-bff/src/main` → 0。**整条 KB 链路无任何手写 JPQL**。
- **风险性质变化（要点）**：派生查询降低的是**写错的概率**（省掉实体名/别名/参数绑定三类手写面，且同属性的 `findBySessionId` 已长期工作证明 `sessionId` 可解析），**没有改变校验发生的时机**——仍在 EntityManagerFactory 启动时。缺口收窄≠消除。

### 悲观锁四项前提（主理人独立复核清单，可复用）
1. `@Transactional` 非 readOnly（`KbQaService:227`）— 否则锁随查询即刻释放
2. 写路径走加锁版（`:240`），读路径保持无锁（`:187`/`:264`）— 防读放大
3. **非同类自调用**（唯一调用方 `QaController:52` 是外部入口）— Spring 代理自调用会静默失效，最易翻车
4. 行锁管不到的边界有兜底：并发**首次插入**无行可锁，由 `uk_kb_feedback_session UNIQUE(session_id)`（`V12__kb_schema.sql:135`）在落库层兜住 — 已查证约束真实存在
