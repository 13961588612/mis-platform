## 侧栏完整性加固（用户报"系统管理 sidenav 还有菜单没出来"）

### 根因
- 侧栏数据流：`app-layout.tsx` → `navNodes = routerMenusToSystemNav(menus) ?? SYSTEM_NAV` → `SideNav`。
- `?? SYSTEM_NAV` 兜底**仅在后端返回空集合时触发**；一旦后端返回**任意非空但残缺**集合，就整体覆盖完整的静态 `SYSTEM_NAV` → 侧栏出现"菜单不全"。
- 最可能的真实诱因：V9 迁移（`V9__add_missing_system_menus.sql` 授予 281/285/289/293 四个新页面给 role_id=1）尚未对运行库执行（DB 停在 V8），后端 `/menus/router` 只回 V8 及更早的菜单，于是残缺集覆盖了静态全量。

### 前端加固（已落地，typecheck 0 错误）
- `lib/nav/menus-to-nav.ts`：新增 `mergeNavWithFallback(fallback, dyn)` —— `SYSTEM_NAV` 作为系统子系统的**权威骨架**，后端动态菜单仅对同 path 的叶子做 title/icon 增强；绝不产生空洞。
  - 新增本地 `flattenLeaves(nodes)`（因 `flattenSystemNavLeaves()` 无参，无法直接复用，故自建）。
- `components/layout/app-layout.tsx`：`app.code === 'system'` 时改用 `mergeNavWithFallback(SYSTEM_NAV, dyn)`；其余子系统仍用 `dyn ?? SYSTEM_NAV`。
- 效果：即便 V9 未跑 / seed 数据缺失，系统侧栏恒定显示全部 13 个已知路由；V9 一旦执行，同 path 动态叶子覆盖静态 title/icon（无回归）。

### 后端数据修复（已核实正确并加固）
- `V9__add_missing_system_menus.sql`：A.3 授权 INSERT 加 `ON CONFLICT (id) DO NOTHING;`（与 V8 风格一致）防 id 撞键整条失败。
- 权限链已端到端核实：BFF `MenuAggregateService.router()` → IAM `listUserMenuIds` → `sys_role_permission`(perm_type='menu')，V9 写的是正确表。
- V9 path 归一化 CASE 正确处理 V8 module 菜单（`code='module' → '/system/module'`），不引入新 404。

### 待办（沙箱受限，无法本段执行）
- 真实执行 V9 迁移至运行库（需 PG + JDK17 起服），使 RBAC 级菜单隐藏生效。
- Phase D：回写 `schema-design.md` 去 sys_api ER 图的 app_id（已部分做）+ 清理 `page-defs.ts` 陈旧的 `/system/module` def。
