## 多 Agent Gateway 并发部署 —— 架构评审（规划中，未开工）
- 需求：用户要"同时部署多个 agent gateway"，报告 3 个已知问题（会话粘滞 / gateway 掉线 / 多 gateway 交叉消费出站事件只看到部分回复），并要"同步思考其他问题"。
- 走「部分工作流=架构评审」：TeamCreate `software-agent-gateway-multi` → 架构师(高见远) 出方案，未编码。
- 已查明根因（读码）：
  - 所有 gateway 共用消费组 `gateway-event-group`（`gateway/src/index.ts:284`）消费全局 `aip:stream:agent:events`（`backend/.../queue/redis_stream.py:29`）。Redis 消费者组分片语义 → 事件被均摊到各 gateway，但会话的企微 Bot WS 只挂在 owner gateway → 其他 gateway 拿到事件无处投递=静默丢失（即 K3；K1 同一根因）。
  - `BotRegistry`（`gateway/src/channels/BotRegistry.ts`）进程内存、且 `startAll` 每实例启动全部 bot（L138），违反企微"一 bot 一 WS"硬约束，且无分布式租约/故障转移（K2/N2）。
  - 两个消费组（gateway-event-group、agent-core-group）都无 XAUTOCLAIM/XPENDING 重投（N1 崩溃静默丢）。
  - 另补 N3 sessionId 不含 botId 碰撞、N4 接管脑裂/半开、N5 H5 WS 无粘滞且 wecom-h5 每次随机 sessionId、N6 入站写前崩溃、N7「每 gateway 独立组读全量」反向→重复投递。
- 推荐方案：① 按 owner 分流 stream key（每 gateway 独立 `aip:stream:gw:{ownerGwId}:events`，Agent Core publish 时查 `aip:bot:{botId}:owner` 后 XADD）+ ② Redis 租约（SET NX+TTL+心跳）让每 bot 全局恰好一个 owner gateway。分 4 阶段落地（bot 所有权+出站亲和 → 崩溃重投 → H5 粘滞 → sessionId 收尾）。
- 关键约束：企微 Bot WS 是服务端单连接，多活热备不可行；H5/wecom-h5 是客户端 WS 可用 sticky LB。本期仅多 Gateway，Agent Core 保持单实例（多实例是同构风险，已留接口）。
