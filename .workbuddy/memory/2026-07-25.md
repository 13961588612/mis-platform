## 契约核对：BFF /ai/features 与前端注册表断链（阻断页面内 4 个 AI 按钮）

## UI 设计：数据依赖顺序校正（用户追问 app/module/api 在 menu 之前）
- 用户指出菜单是下游、应先有 app/module/api 管理。核对 schema：三张表真实存在且在菜单上游，原 prototype 导航+Brief 清单都漏了它们。
- 真实 FK：tenant(种子) ← app(tenant_id)；module 平台级、无 tenant/app 隶属(独立)；api 同时需 app_id + module_id；menu 需 app_id 且经 sys_menu_api 绑定 api；role 需 app_id 且经 sys_role_permission 分配 menu。
- **校正用户顺序**：api 不是最先（api 依赖 module+app）。正确录入序 = 模块(①独立) → 应用(②) → API(③) → 菜单(④,已做) → 角色(⑤)。module 与 app 可互换前置，但都先于 api。

## 排查：AI 四按钮改完映射后仍不显（运行时，非代码 bug）
- 用户实测映射修复后 4 按钮仍不显，但 BFF `/api/v1/ai/features` 返回正确（features 全 true、config.form-fill.confThreshold=0.85）。
- 静态全链路逐行核对均正确：ai-context.tsx 改动已落地(16-27 纯函数 + 64-66 计算)、api client `baseURL:'/api/v1'`、response 拦截器 `return response`(res.data=body)、ai-store.setFeatures 置 featuresLoaded=true、ai-feature.tsx 门禁(24-28 行)正确、AIProvider 挂载于 router.tsx:39 应用根、isAuthenticated 逻辑正确。
- **根因（运行时）**：AIProvider 的 effect 依赖 `[location.pathname, accessToken, setFeatures, setHealth]`，Vite HMR 热替换 ai-context.tsx 后依赖未变 → effect 不重跑 → store.enabledFeatures 仍是初始空 → 按钮继续 hide。copilot 能聊与此无关（走 useAI 不碰 enabledFeatures store），故出现「能聊但按钮不显」分裂现象。
- **解决**：浏览器硬刷新(Ctrl/Cmd+Shift+R) 让 AIProvider 重新挂载执行 effect→拉 features→按钮显。映射修复本身正确且必要（旧代码 d.enabled 恒 undefined 必空）。
- **兜底诊断**：硬刷新后仍不显→DevTools Network 看 /ai/features 是否 200+data.features 全 true；Console 看报错；或在 ai-context effect 内 setFeatures 前临时 console.log payload 确认执行与返回。
- **沙箱限制（实测）**：本环境无 `agent-browser` 技能、node_modules 无 playwright/puppeteer；网关登录 `POST /api/v1/auth/login` 真实环境要验证码（`{"appCode":"system","username":"admin","password":"Mis@123456","captchaId":"it","captchaCode":"it"}` 返回 `验证码错误`），无头脚本拿不到 token，故无法自动驱动用户已登录的浏览器。dev server(:5173) 已确认在服务新版模块（curl 模块含 `translateCapabilitiesToFeatures`）。
- **临时调试角标**：在 `ai-context.tsx` 内新增 `AiDebugBadge`（仅 `import.meta.env.DEV` 渲染，左下角绿框），实时显示 authed/token前8位/featuresLoaded/health/enabledFeatures。用途=用户硬刷新后 5 秒读出真因（effect 没跑/请求失败/其他）。定位后须删除此角标。
- **进一步：AiFeature 可视化调试壳**。用户硬刷新后仍报 4 按钮不显，但角标显示 features 已正确加载。为远程定位，在 `ai-feature.tsx` 内新增 dev-only `AiDebugBadge`：当 `enabled=false` 时不返回 null，而是渲染红色边框标签显示 `feature/loaded/enabled/features`；当 `enabled=true` 时在 children 左上角渲染绿色小标签。这样只要截图页面就能判断是「门禁 false」还是「渲染了但看不见/被遮挡」。typecheck 通过。定位后须删除此诊断壳。
