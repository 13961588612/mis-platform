## 用户新问题：copilot 动态界面组件 vs HITL（概念澄清）
- 用户问：动态生成界面→顾客操作→再弹新界面，属于 HITL 吗？在规划里吗？外置合适吗？
- 核实：ai-platform **后端 src 与 frontend/src 均无 ui_schema/dynamic component schema 概念**（grep=0）；HITL = ApprovalStore(审批) + FormFillPendingStore(表单，其 candidates/field 即"动态界面"渲染数据) 两类，已随上轮迁 Redis。
- 结论框架：
  1. **动态 UI ≠ HITL**：动态 UI 是"交互呈现层"（客户端渲染 agent 输出的结构化界面）；HITL 是"控制流层"（agent 暂停执行、等用户输入恢复）。正交但常绑定出现。
  2. 判定：操作后 agent 需"暂停等该操作结果才能继续"→ 就是 HITL；纯消息往返+富媒体渲染 → 非 HITL（历史已 Redis 可重放）。
  3. 规划覆盖：表单/审批两类 HITL 在规划内且已外置；动态 UI 渲染数据不在（也不需要在）外置范围。
  4. 外置准则：**只外置"恢复点状态"（pending 记录/resume_token/已填字段/状态），不外置"渲染数据"（界面 schema 可重算）**。HITL 挂起态小、结构化、正确性关键 → 外置合适（已做）；UI 渲染数据大、可重算 → 不外置，靠软亲和兜底进程内交互态。
  5. 待核实项：若存在"表单/审批之外"的动态 UI 多步交互态（运行时 interrupt 型、非 HITL store），当前规划未显式覆盖 → 限流恢复后派工程师核实 copilot 动态 UI 交互态挂在哪层（消息驱动 vs 运行时 interrupt vs 客户端状态），决定是否需扩展 HITL 外置范围。

## CopilotKit ↔ A2UI 关系澄清（15:00-15:15，WebSearch 实证）
- 用户质疑"CopilotKit 不是官方 A2UI 方案吗？怎么协议不兼容"——**实证结论**：
  - **A2UI = Google 主导的开放 Declarative Generative UI 规范**（平台无关）；CopilotKit 只是 **launch/design partner**（zero-day 支持），非 A2UI 本身；官方实现是 @ag-ui/* + @a2ui/*（ag-ui.dev / a2ui.org）
  - **AG-UI（传输协议）≠ A2UI（UI 规范）**：A2UI 搭载在 AG-UI 的 CUSTOM events 上传输；官方原话"Any agent already speaking AG-UI can drive A2UI without touching agent code"——我们的 Gateway(@ag-ui/a2ui-middleware) 走的正是官方标准路径
  - **CopilotRuntime 对 agent 无"具体框架"硬要求，要求的是"能讲 AG-UI"**，三种接入：① BuiltInAgent 简单模式(model 字符串)/工厂模式(type=aisdk|tanstack|custom) ② 13+ 官方框架 adapter（LangGraph/ADK/Mastra/CrewAI 等，经 HttpAgent 走 AG-UI）③ 自定义后端 factory mode（type:"custom"，factory 自己 fetch 后端并把流转成 AG-UI BaseEvent——官方明确支持"any server, without requiring an agent framework"）
  - **关键发现**：CopilotRuntime `a2ui: true` = 自动给 agent 挂 **A2UIMiddleware**（与 Gateway 要用的 @ag-ui/a2ui-middleware 同源，宿主不同：CopilotRuntime route vs 自建 Fastify Gateway）；前端绑定 @copilotkit/react-*
  - **对 MIS 场景**：接 CopilotRuntime 仍需自写 Redis Streams→AG-UI BaseEvent 桥接（≈ EventConverter 成本）+ MIS 私有逻辑（双 JWT/权限码/渠道/粘滞会话）CopilotRuntime 不提供 + 前端换 CopilotKit 全家桶 → **自建 Gateway 挂官方中间件更直接，07"不采纳 CopilotKit"结论方向不变**，但理由精确化为"运行时体系不同（CopilotRuntime vs AG-UI 官方链路）+ 僵尸依赖"，而非"协议不兼容"（协议其实是兼容的，CopilotKit 恰恰支持 A2UI）
