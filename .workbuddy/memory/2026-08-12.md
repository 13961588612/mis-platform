## 🔍 MCP「实时探测」功能机制（2026-08-12 13:51，用户要求只聚焦此功能）
- **不是轮询**：无 setInterval/WebSocket。触发仅两种——① 打开页面 `load()` 时 `Promise.allSettled([listMcpServers(), getMcpServersHealth()])` 一次性探活（失败只降级该列显示「未探测」）；② 表格上方「健康探测」按钮 `refreshHealth()` 手动重拉。
- **链路**：前端 `getMcpServersHealth()` → BFF `GET /agent-ops/mcp/servers/health` → ai-platform `GET /api/v1/mcp/health` → `manager.health_check_all()`（`manager.py:135`）→ 遍历 `self._clients`（**仅已连接**）调 `client.health_check()` → 返回 `{name:bool}` → BFF 剥 `data` 层。
- **三态判定**（前端 `health[name]`）：`true`=探测正常；`false`=探测异常（在 `_clients` 但 `is_connected=False` 或 `list_tools()` 抛异常）；`undefined`（键不存在）=未探测（**根本没连上，不产生结果**）。
- **关键坑**：`client.is_connected`（`client.py:114`）是朴素内存标志（`connect()` 置 True/`disconnect()` 置 False），**不校验 socket 存活**；真正的探测动作只有 `health_check()` 里那次 `await self._session.list_tools()`（`client.py:219`，try/except 包住，抛异常→False）。所以"一直异常"=连上了但 `list_tools` 失败（Server 中途挂/网络断/`tools/list` 畸形），**不是没连上**（没连上显示「未探测」）。
- 排查顺序：先看异常还是未探测 → 异常则页面「断开」再「连接」刷新链路 → 仍异常用 MCP Inspector 直连 Server 跑 `tools/list` 确认 30s 内能返回合法 tool → 平台客户端不发 auth 头，Server 依赖 Authorization 也会探活失败。
