## 🔴 超市十坑（违反即错数 · 完整版见 01/02/12）
1. **生鲜判定恒为 `goodstype='1' AND deptlevelid='4'`**（小类层）；枚举 A 级定案 = **1 生鲜/2 食品/3 非食品**（旧表业态外(2/3/4)/大类码('9')/普通('0') 三条已作废，常规品 `IN('2','3')`）。层级 = **1 柜组/2 大类/3 中类/4 小类**（42/264/1405/6784=8495，主键唯一）。
2. **`goodstype` 完全由 `categoryid` 首段决定，零例外** → 是 id 编码的投影非独立标签，改类型须改编码体系；**沿层级继承** → 读父行只得二值结论（0%/100%），**占比/清单类必须走小类上卷**。
3. 🔴 **层级聚合一律 `GROUP BY categoryid, categoryname`，禁按 name**（v12 实测按 name 把 396 生鲜小类压成 389，吞掉 7 个）。
4. 🔴 **同比须剔四类结构性低谷窗口**（春节前 24 天 / 3 月初 10 天 / 11 月初 5 天 / 2025-02-25）：**窗口类分析按具体日期区间分组**（按月分会把 10 天真低谷稀释进 52 天）。**3 月初 = 妇女节百货大促**（总盘 1.73x，生鲜涨幅最慢 → 分母效应不是干货挤占）；春节前 = 食品年货撑大盘。
5. 🔴 **报损双口径并列**：纯损耗 `SUM(-shhsje WHERE shhsje<0)/销售额` ≈3.11%（主）+ 绝对值 `SUM(ABS(shhsje))/销售额` ≈3.88%（对照）；净额不报；**Top 损耗 `ORDER BY shhsje ASC`**；正损耗行 = 冲回/退货（不是损耗）。
6. 🔴 **报损尖峰 = 账实差异【双向账务重算】不是真实损耗**（四点互证：24/43 天 >100%、最高 219.22% 物理不可能｜销售端无异常｜白猪链 5 节点 43/43 天正负净额=0 闭合｜上架类目数差异 0.066%）。盘点制度：14 号日均损耗 = 其他日 17.2 倍、月末 27-31 = 5.5 倍、43 天扛 65.6% 金额。**「报损率 > 30%」= 盘点日自动识别规则**（两区间零重叠）但漏检 2025-11-30 → 🔴 **主口径必须用手写 43 天清单**（`tools/loss_spike_days.py`，与 `_calc_v18.py` SP43 交叉校验一致）、规则只作交叉校验；🔴 **「14 号 + 月末 27~30」的日期模式规则同样不可替代** —— 实测该规则在 658 天里多命中 64 天（1/2/6 等月份没做月末盘点）→ 过度剔除 → 常态口径算错；🟢 **剔日只用【区间内】的日期**（如 2026-06 只 06-14/06-29 两天），别贴全量 43 天 —— 模型要学的是「识别区间内盘点日」的方法；🔴 **常态口径只在区间统计时才有意义**（单日剔无可剔）→ 报损率样本须**四口径并列**（纯损耗/绝对值 × 全期/常态）。🟢 常态报损率逐年改善（3.80%→3.29%）=【报损管理在改善】非【波动】。
7. 🔴 **答「损耗吃掉多少毛利」必须拒绝**（损耗是独立第三个金额科目，不是扣减项）。
8. 🔴 **cost 表无 `turnover_amt`/`xsje`** → 报损率分母只能从 cpi 取 `xsje`；**分子分母各自子查询按月聚合再 JOIN**（两表明细行数不 1:1，直接 JOIN 放大行数；cpi 表无 `goodstype` 列，跨表写 `c2.goodstype` 直接报错）。**cost 比销售表多 88 节点**（物料成本是 2025-08~12 一次性事件，2026-04 起归零）。
9. 🟢 **三档生鲜口径（待业务方拍板）**：A 现状 47.21%｜C 生鲜+日配 26.54%｜B 狭义鲜品 13.71%。**落地用父中类 id 白名单**，禁名称关键词（漏网 39.90%）。已销售小类 1,272 = 生鲜 396 + 食品 404 + 非食品 472；4/5/7/9 段 384 个零销售（从未启用，非漏计）。
10. 🔴 **类目名 CHAR(20) 按显示宽度 20 定长补空格**（显示宽度集合 = {20}，零例外）；3,409 行含尾随空白 → **2,742 可自动 TRIM / 667 需人工**。**检索用 TRIM、定位用 id、聚合禁按它分组**。

## 📌 方法论（FDE 复用 · 十条）
1. 🔴 **真查优先于文档转述** —— 文档可能落后于 reality（本次即查出 catalog 登记停留在旧表）。
2. 🔴 **两次读数冲突 = 找差异维度**（表/环境/版本/过滤），不是挑一个信；门禁必带**「枚举基数」列**。**换表 + 换环境会让两次读数各自自洽且都对** → 先怀疑环境换了。
3. 🔴 **结构问题禁靠总量减法推**（「父级缺失数」≠「顶层行数」）→ 断链/孤儿一律实测，推算值单标「待实测」。
4. 🔴 **结论反转必须同步划除旧表述**（全库扫旧关键词，旧句 `~~划除~~`），**生成器也要改**否则重跑又生成旧文案。
5. 🔴 **口径每条写「主口径 + 对照口径 + 依据」三段**；**定案前找第二条独立证据（三点互证）**；相关系数不显著时说「无稳定关系」。
6. 🔴 **比率 > 100% 是非业务量标志** → 越界即定性；**异常分析必须同时看正向与负向金额分项**；**「配对」是日常现象，判别盘点日看金额量级**。
7. 🔴 **波动指标先看逐日分布**；**采样偏差伪装成「口径稳定」**（极差随样本量单调不减）。
8. 🔴 **`COUNT(*)` 是明细行数不是天数**；**窗口/分组粒度必须与行为发生区间对齐**；**返回 0 行先怀疑 join 键的层级**（`dim_type_id` 存小类 id，join 后按 `deptlevelid='3'` 过滤必空）。
9. 🔴 **CHAR 定长按显示宽度判定不是字节**（汉字数 = (LENGTH-CHAR_LENGTH)/2）；**先确认 `LENGTH()` 是字节还是字符**（该环境中文按 3 字节计，「偶数」与「3 的倍数」同源，不能互为证据）。
10. 🔴 **注释写了正确做法但代码没改 = 事实上的错误 SQL**；**生成器用中文字符串锚点定位文档章节 → 锚点失效则段落静默变空不报错**；**改文档引用 ≠ 改磁盘文件名**；🔴 **文档多到影响推进时 → 收敛为「1 主计划 + 每项 1 详细文件」，其余降级归档件不并行更新**；🔴 **分清「交付物」与「验收动作」——用户要的是可直接入库的样本条目，不是本地跑一遍的核对 SQL**（本次纠偏：先做成了「本地跑 SQL + 填期望值/实测值」，被用户打回）。🔴 **样本 remark 必须四要素齐全（档位 data_type / 门店 / 日期 / 口径约束），且【从 SQL 自动反解】而非手写**（`build_remark()` + `_extract_slots()`）—— 手写必详略不一；档位漏了 = 模型学到「不按档位过滤」= 数字翻倍。

> 📌 **完整内容见同目录 `PLATFORM_RULES.md`**（MEMORY 只留指针，避免注入截断）。
> 最常用的 6 条：
> 1. **登录链路带 `/api/v1/auth` 前缀**：`GET /api/v1/auth/captcha?appCode=system`（SVG，正则 `<text>` 取 4 位码）→ `POST /api/v1/auth/login`（admin/Mis@123456）；**token 字段名 `accessToken`**；业务成败看 JSON `code`（HTTP 恒 200）。
> 2. 🔴 **门禁 OOM 极具误导**：前端只用 **pnpm**（npm 必崩）；`exit 1`+空输出 = OOM kill ≠ 代码错。测试 `NODE_OPTIONS="--max-old-space-size=700" npx vitest run --pool=threads --poolOptions.threads.singleThread=true`；类型 `node --max-old-space-size=4096 ./node_modules/typescript/bin/tsc --noEmit`。**串行跑 + `run_in_background` + 绝对路径日志**；700MB 跑大目录整组 OOM（尤其 `biz/forms`）→ 改**精准子集 + 1536MB**。

> 4. 🔴 **BFF 三大坑**：①**deny-unmapped**（每端点须登记 `sys_api` + 绑授权菜单，否则 403 静默失效）②**出站 URI 编码**（`builder.toUriString()` 喂 `WebClient.uri(String)` 会二次编码 → 非 ASCII 恒 0；✅ `uri(Function)` + `{qN}` 占位 helper）③**构建/进程过期伪装成代码缺陷**（判新代码看进程启动时间，别信 jar 时间戳）。
> 5. 🔴 **前端坑**：表格吸顶 `min-h-0 flex-1 overflow-auto`；`cn()`=tailwind-merge 只同类组去重；`keep-alive-outlet` 页面**不在 Route 上下文** ⇒ `useParams` 恒空（动态路径登记 `DYNAMIC_PAGES`）；`auth-store` 是 zustand persist ⇒ `SessionBootstrap` 绝不能早退；**mock 残留让回归门假绿** → `afterEach` 必须清 mock + 变异验证。
> 6. **菜单授权真值源 = `sys_role_permission`**（`perm_type='menu'`），**无 `sys_role_menu` 表**；**新菜单必须迁移补授权**，否则按钮被 `PermissionGate` 静默隐藏。
