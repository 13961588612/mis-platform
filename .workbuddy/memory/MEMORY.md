## 🔴 BFF 三大坑
1. **deny-unmapped**：每端点须登记 `sys_api` + 绑授权菜单，否则 403 且**静默失效**。给已有端点加可选 query 参数 path_pattern 不变 ⇒ 无需重新登记。
2. **出站 URI 编码**：`builder.toUriString()` 喂 `WebClient.uri(String)` 会二次编码 → 非 ASCII 恒 0。✅ 用 `uri(Function)` + `{qN}` 占位 helper；❌ 禁 `.build(true)`。⚠️ `buildAndExpand(...).toUriString()` 本安全勿误判。
3. **构建/进程过期伪装成代码缺陷**：接口缺字段常因跑旧构建。重建 `build-dev.ps1 <svc>` + `start-dev.ps1 <svc> -Restart`；判新代码看进程启动时间，别信 jar 时间戳。`ApiPermissionRegistry` 异步灌 300s ⇒ 头 20s 全 40300。

### 📌 通用方法论
- 🔴 **两次读数冲突通用解法**：不是挑一个信，而是**找出差异维度**（表/环境/版本/过滤）；健康度门禁必带**「枚举基数」列**（`COUNT(DISTINCT)`）
- 🔴 **结构问题禁靠总量减法推**（「父级缺失数」≠「顶层行数」）→ 断链/孤儿一律实测；推算值单独标注「推算，待实测」
- 🔴 **结论反转必须同步划除旧表述**（搜旧关键词全库扫，旧句用 `~~划除~~`）；**生成器也要改**，否则重跑又生成旧文案
- 🔴 **口径文档每条写「主口径 + 对照口径 + 依据」三段**（单一口径遇新证据必被推翻）
- 🔴 **异质符号分组要看第三个金额列的分布**（分布差异极大 = 另一类业务）
- 🔴 **注释写了正确做法但代码没改 = 事实上的错误 SQL** → 改完必须 grep 验证代码本身
- 🔴 **推断链逐环验证**（「A 与B 反号 ⇒ A 是C 组成部分」是两环推断）
- 🔴 **下限类推算禁拿总量减法**（同上）
- 🔴 **窗口/分组类分析要检查粒度是否匹配**：分组键必须与【该行为的发生区间】对齐，不能用粗粒度时间桶；自检 = 把组内【关键子集】单独算一遍，与全组均值对比，差太多就是粒度错配
- 🔴 **异常事件清单先做【日期维度聚类】**（几号/周几/日期间隔）—— v14 从 43 个尖峰日一次定位到「半月盘点制度」；按金额排序看不出周期性
- 🔴 **判别「集中 vs 普涨」必须同时看【参与实体数】与【单实体强度】** —— 尖峰日有损耗节点数 542 不变、超千节点 28→129 ⇒ 是集中核销不是普涨
- 🔴 **分析字符串长度前先确认 `LENGTH()` 是字节还是字符**：用「长度 % 3 == 0 的占比」检验（UTF-8 中文下字节长必为 3 的倍数）；**同源的两个信号不能互为证据**
- 🔴 **`COUNT(*)` 是明细行数不是天数** —— 引用前用「行数 ÷ 每行实体数」反算校验
- 🔴 **方向性假设也可能是反的，必须跑对照实测**：v11 推断「空白造成假重名 → TRIM 后减少」，实测【增加 36%】→ 做法 = 同一份数据跑两个口径对比，差值方向即真相
- 🔴 **采样偏差会伪装成「口径稳定」**：极差随样本量单调不减，小样本算极差必然低估波动；凡宣称「稳定/一致」必须用【全量】或【分层随机】样本

- 🔴 **波动指标必须先看逐日分布**：月度极差可能全由少数尖峰造成（v13：3 天占 78.7%，剔除后结论反转）；做法 = 找出 >3x 中位数的日子 → 剔除后重算 → 看结论是否还成立

- 🔴 **窗口/分组类分析要检查粒度是否匹配**：分组键必须与【该行为的发生区间】对齐，不能用粗粒度时间桶；自检 = 把组内【关键子集】单独算一遍，与全组均值对比，差太多就是粒度错配
