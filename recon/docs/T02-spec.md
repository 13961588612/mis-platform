## 2. 全局转换规则与类型映射（锁定）

### 2.1 方言对照（技术适配 §2.1 落地版，逐条执行）

| # | Oracle 写法 | PG 等价（本工程锁定） | 备注 |
|---|---|---|---|
| 1 | `VARCHAR2(n CHAR)` | `VARCHAR(n)` | 按字符计长，中文安全 |
| 2 | `NUMBER`（通用） | 按 §2.2 语义细分：`BIGINT` / `INTEGER` | 不再用裸 NUMERIC |
| 3 | 金额 `NUMBER(20)`（整数分） | **`BIGINT`** | 全部 `*_cent` 列；范围论证见技术适配 §2.1 |
| 4 | `NUMBER(1)`（布尔） | **`SMALLINT`**（保持 0/1） | JPA `Integer` 映射 |
| 5 | `CLOB`（JSON） | **`JSONB`** | 列清单见 §4 |
| 6 | `CLOB`（长文本非 JSON） | **`TEXT`** | gate_sql / key_scan_sql / agg_sql / content 等 |
| 7 | `DATE`（含时分秒） | **`TIMESTAMP`**（无时区，Asia/Shanghai） | 例外：`biz_date` 取日语义用 `DATE`（见 §3.9） |
| 8 | `SYSDATE` | `now()` | 默认值 `DEFAULT now()` |
| 9 | `SYSDATE - N` | `now() - interval 'N days'` | 运行期 SQL，DDL 不涉及 |
| 10 | `TRUNC(record_time)`（取日） | `CAST(record_time AS date)` / `date_trunc('day', record_time)` | biz_date 写入侧 |
| 11 | `GREATEST(a,b)` | `GREATEST(a,b)` | PG 原生支持，运行期 SQL |
| 12 | `GENERATED BY DEFAULT AS IDENTITY` | **`BIGSERIAL`** | 19 表 id 列；JPA `IDENTITY` 兼容 |
| 13 | `CREATE SEQUENCE ... CACHE 1000 NOORDER` | `CREATE SEQUENCE ... CACHE 100` | PG CACHE=每会话预取，勿照抄 1000 |
| 14 | `seq.NEXTVAL FROM dual` | `nextval('recon_update_seq')` | 无 FROM DUAL |
| 15 | `MERGE INTO ...` | `INSERT ... ON CONFLICT ... DO UPDATE` | 运行期 SQL（§2.3），DDL 不涉及 |
| 16 | `FETCH FIRST n ROWS ONLY` | `LIMIT n OFFSET m` | 运行期 SQL |
| 17 | `ROWNUM <= n` | `LIMIT n` | 运行期 SQL |
| 18 | 唯一索引 `NULL != NULL` | 同 PG 默认；`pair_segment DEFAULT '-' NOT NULL` 已规避 | 无需 `NULLS NOT DISTINCT` |
| 19 | `user_tab_columns` 自检 | `information_schema.columns` | 见 §7 |
| 20 | `VARCHAR2(2000 CHAR)` err_msg 等长文本 | **`TEXT`** | 防超长截断 |

### 2.2 类型映射口径（NUMBER 语义细分，锁定）

| 语义 | 目标类型 | 适用范围 |
|------|----------|----------|
| 金额（整数分） | `BIGINT` | `*_cent` 列：amount_cent、diff_amount_cent |
| ID / 序列值 / 水位 / 游标 / 版本 / 关联外键 | `BIGINT` | 全部 `BIGSERIAL` id；update_seq、committed_seq、cursor_seq、pending_peer_pull_run_id、detail_id（两表） |
| 计数 / 序号 / 秒数 / 天数 / 量值 | `INTEGER` | fetch_overlap_sec、agg_key_batch_size、pool_max_age_days、pending_max_wait_hours、seq_no、min_wait_min、max_wait_min、row_count、insert_count、update_count、clock_skew_ms、reopen_seq、matched_count、diff_count、resolved_count、retry_count、report_run.diff_count |
| 布尔 | `SMALLINT` | 全部 `NUMBER(1)` 列（见 §3 各表 / §4.4） |
| 时间（含时分秒） | `TIMESTAMP` | 全部 DATE 列，例外 biz_date 用 `DATE` |
| 业务日（TRUNC 到日） | `DATE` | 仅 recon_source_record.biz_date（报表归属按日，PG 纯日期语义准确） |
| 原始态金额字符串 | `VARCHAR(64)` | amount_raw（白名单，不进 BIGINT） |
| 方向枚举 | `VARCHAR(8)` | amount_direction（in/out/none，非金额数值，自检白名单） |

> 约束：`information_schema.columns.data_type` 中 `BIGINT`→`bigint`、`INTEGER`→`integer`、`SMALLINT`→`smallint`、`VARCHAR(n)`→`character varying`、`TEXT`→`text`、`JSONB`→`jsonb`、`TIMESTAMP`→`timestamp without time zone`、`DATE`→`date`（§7 自检 SQL 依赖此口径）。

### 2.3 序列与身份列（锁定）

```sql
-- 原 Oracle: CREATE SEQUENCE recon_update_seq START WITH 1 INCREMENT BY 1 CACHE 1000 NOORDER;
CREATE SEQUENCE recon_update_seq START WITH 1 INCREMENT BY 1 CACHE 100;
-- 发号：SELECT nextval('recon_update_seq')；台账 upsert 用 nextval('recon_update_seq')（技术适配 §2.3）
```

- 19 张含 `id` 的表：`id BIGSERIAL PRIMARY KEY`（替代 Oracle GENERATED BY DEFAULT AS IDENTITY；PG 10+ 亦可 `GENERATED BY DEFAULT AS IDENTITY`，本工程锁定 BIGSERIAL + JPA IDENTITY 兼容，技术适配 §2.1 #12）。
- 唯一例外：`recon_seq_watermark` 无 id，主键 `ds_code VARCHAR(64) PRIMARY KEY`（原文如此，保持不变）。

```sql

    id           BIGSERIAL PRIMARY KEY,
    ds_code      VARCHAR(64)  NOT NULL,
    record_key   VARCHAR(256) NOT NULL,
    record_data  JSONB NOT NULL,                -- 整行数据 JSON（值一律字符串存储）

    biz_date     DATE,                          -- 业务日 TRUNC(record_time)，PG 纯日期

    last_pull_run_id BIGINT,
    created_at   TIMESTAMP DEFAULT now() NOT NULL,
    updated_at   TIMESTAMP DEFAULT now() NOT NULL

CREATE INDEX idx_source_seq  ON recon_source_record(ds_code, update_seq);
CREATE INDEX idx_source_time ON recon_source_record(ds_code, record_time);
```

## 6. V2__quartz_pg.sql 方案

### 6.1 内容与来源（已核对）

- 内容：quartz-2.3.2.jar 内 `org/quartz/impl/jdbcjobstore/tables_postgres.sql`（207 行）**原样复制**为 `db/migration/V2__quartz_pg.sql`，不做任何改写。
- 版本同源：Spring Boot 3.2.5 BOM `quartz.version=2.3.2`，与本地 m2 `quartz-2.3.2.jar` 一致（已核对），脚本与运行时 Quartz 完全对齐，无版本漂移风险。
- 脚本组成：开头 11 个 `DROP TABLE IF EXISTS` + 11 张表 + 20 个 `CREATE INDEX` + 末尾 `COMMIT`。
- **表数量核对**：官方脚本实际创建 **11 张** QRTZ 表（QRTZ_JOB_DETAILS / QRTZ_TRIGGERS / QRTZ_SIMPLE_TRIGGERS / QRTZ_CRON_TRIGGERS / QRTZ_SIMPROP_TRIGGERS / QRTZ_BLOB_TRIGGERS / QRTZ_CALENDARS / QRTZ_PAUSED_TRIGGER_GRPS / QRTZ_FIRED_TRIGGERS / QRTZ_SCHEDULER_STATE / QRTZ_LOCKS）。任务分解/技术适配表述"QRTZ 12 表"为计数出入（Quartz 2.x JDBCJobStore 即 11 张表），**以官方脚本实际内容为准**。

### 6.2 注意事项（无需改动项）

| 项 | 结论 |
|----|------|
| 开头 11 个 DROP TABLE IF EXISTS | Flyway 安全：迁移版本控制下每个脚本只执行一次，DROP 仅作幂等兜底，干净库无影响；重复执行（人为回滚后重跑）也安全 |
| schema 前缀 | 脚本无 `public.` 前缀，Flyway `default-schema=public` + 连接 search_path 默认 public → 表建在 public；Quartz `LocalDataSourceJobStore` 用同一数据源连接，无前缀 SQL 走 public → **无需改动** |
| SCHED_NAME | `VARCHAR(120) NOT NULL`，Quartz 写入时取 `application.yml` `org.quartz.scheduler.instanceName=reconScheduler` 作为 SCHED_NAME 值 → **无需改动** |
| BOOL / BYTEA 类型 | PG 原生类型，配合 `driverDelegateClass=PostgreSQLDelegate`（application.yml 已锁定）兼容 |
| 末尾 COMMIT | Flyway 在 PG 上默认事务性执行 DDL；脚本内 COMMIT 提前提交 DDL 属官方脚本既有行为，风险可接受。**保持原样**（任务要求"原样纳入"，便于与上游比对升级） |
| 与业务表冲突 | QRTZ_* 与 recon_* 前缀不重叠；V1 只建业务表，V2 只建 QRTZ，互不依赖，版本号顺序 V1 < V2 无冲突 |

### 6.3 Quartz 配置联动（T01 已锁定，T02 不改）

- `spring.quartz.job-store-type=jdbc`、`spring.quartz.jdbc.initialize-schema=never`（QRTZ 表由 Flyway 管，绝不自动初始化）。
- `mis.recon.scheduler.enabled` 默认 false；T02 建表完成后置 true（`RECON_SCHEDULER_ENABLED=true`），调度器随 V2 落表可启动。

## 7. 金额三态律自检 SQL（PG 版）

### 7.1 自检规则（锁定）

- 计算态：`_cent` 结尾列必须 `data_type = 'bigint'`（整数分）。
- 白名单：`amount_raw`（原始态字符串，不进 BIGINT）、`amount_direction`（方向枚举 in/out/none，非金额数值）。
- 违规定义：① `_cent` 结尾但非 bigint；② 列名含 `amount` 但非 `_cent` 结尾且不在白名单。

### 7.2 主 SQL（违规扫描，验收用，期望 0 行）

```sql
SELECT table_name, column_name, data_type
FROM information_schema.columns
WHERE table_schema = 'public'
  AND (
        (column_name LIKE '%\_cent' AND data_type <> 'bigint')
     OR (column_name LIKE '%amount%'
         AND column_name NOT LIKE '%\_cent'
         AND column_name NOT IN ('amount_raw', 'amount_direction'))
  )
ORDER BY table_name, column_name;
-- 期望输出：0 行（无违规）
```

### 7.3 辅助 SQL（全量金额列盘点，人工核对用，期望恰好 4 行）

```sql
SELECT table_name, column_name, data_type
FROM information_schema.columns
WHERE table_schema = 'public'
  AND (column_name LIKE '%amount%' OR column_name LIKE '%\_cent')
ORDER BY table_name, column_name;
-- 期望输出恰好 4 行：
--   recon_detail.diff_amount_cent   bigint                （计算态金额，合法）
--   recon_source_record.amount_cent bigint                （计算态金额，合法）
--   recon_source_record.amount_raw  character varying     （原始态白名单，合法）
--   recon_source_record.amount_direction character varying（方向枚举白名单，非金额值，合法）
```

### 7.4 对任务分解 Oracle 版自检 SQL 的两处修正（规格裁定）

1. **运算符优先级缺陷**：Oracle 版 `WHERE A OR B AND NOT C`（AND 优先）会把合法 `_cent` 金额列（NUMBER）也选出，与"仅 amount_raw 白名单"注释不符。PG 版改为显式括号条件，只报违规。
2. **amount_direction 误报边界**：`recon_source_record.amount_direction`（VARCHAR(8) 方向枚举）命名含 amount 但非金额值；若自检白名单仅 amount_raw（任务分解字面），该列恒被报出、自检永远红灯。**本规格锁定白名单 = {amount_raw, amount_direction}**（见 §7.2 主 SQL），与金额三态律 P-2（只约束金额数值列，列名 `_cent` 结尾）语义一致。

### 7.5 序列发号验证

