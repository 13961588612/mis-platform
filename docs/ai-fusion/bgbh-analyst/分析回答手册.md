# 百购分析回答手册

> 2026-10-17 定稿。后续开发分析功能以本手册为准。
> 分解用哪些表、哪些列，见 [分析能力拆解.md](分析能力拆解.md)。枚举未回填前的限制见 [第一步-枚举与问数范围.md](第一步-枚举与问数范围.md)。

经营日报给数和对比。原因和行动放在用户问「为什么、怎么办」的时候。不要每次出数都写满四层，否则模型会为了填满原因和行动去编。

## 按问题类型写到哪一层

| 用户在问 | 写到哪一层 | 不写什么 |
|----------|------------|----------|
| 多少、排名、占比、是哪天 | 现状 | 不默认写原因和行动 |
| 对比、同比、环比、最近怎样 | 现状 + 趋势 | 没有预计算同比列就写「本次没有同比列」，不编百分比，不做日期偏移 |
| 为什么、差在哪 | 现状 + 趋势 + 原因 | 原因缺因子就写缺。每条原因标「待验证」 |
| 怎么办、接下来看什么 | 上一层再加行动 | 行动只指向下一张表或下一个下钻。不写办活动、调柜、加券 |
| 考核数、正式口径 | 现状 + 口径声明 | 枚举未签字前不写原因，考核流失不当正式考核数 |
| 定义、制度、怎么算的 | 不取数 | 用协调器注入的知识。没有注入就说明这是口径问题 |
| 下个月会不会涨、预测 | 拒绝 | 当前没有预测模型 |

取数题如果表上已经有 `_yoy` / `_mom` 或去年同期表，可以在现状后加一句趋势。这是附带的对比，不是改成分析题。

## 每一层写什么

**现状。** 时间、范围、指标、数值、所用列。金额默认含券 `sale_amt`。用户说去券、去税再换列。全部门店合计时声明未剔除新开店。

**趋势。** 只用预计算列或去年同期小时表。禁止模型自己减日期再算增长率。

**原因。** 只拆 [分析能力拆解.md](分析能力拆解.md) 里有列可对的因子。现在允许用、且不依赖未签字枚举的，只有这些：

- 价、量、折扣：金额、件数、折扣率、去券。毛利率用 `sale_gross_profit_rate`，不重算。
- 结构：门店、厅房、品牌排名。不按经营模式数字编码过滤。
- 客流三因子：客流、转化率、笔单价各有一次取数，才能说差额落在哪一项。`sale_avg_price` 是件单价，不是客单价。
- 关联：写明分母是同品类还是全商场。没有 lift 就不说「关联很强」。

枚举回填之前，不要用这些做原因：新老会员过滤、高端区间过滤、是否类和新客标记、考核流失、按开业时间剔除新店、把账面投入产出比说成发券增量。

**行动。** 一个下钻。沿技能里已有的追问链，带上时间、门店、品牌。

## 开发时怎么改技能

按本手册改回答，不要再把「每次出数都写现状、趋势、原因、行动」写进技能。

| 位置 | 现在 | 按本手册应改成 |
|------|------|----------------|
| `bgbh-router` 第 4.1 节 | 每次出数都要四层 | 改成上表的问题类型 |
| `bgbh-analyst` 系统提示「回答」 | 每次出数按四层写 | 同样按问题类型 |
| `bgbh-s1-daily-report` 回答模板 | 四层都写，原因在用户问为什么才写 | 取数只留现状和可选趋势；为什么才写原因和客流三因子 |
| `bgbh-s4-brand-link` | 已要求写关联度分母 | 保留。趋势、原因仍只在对应问题类型里出现 |
| `bgbh-s5-member-drain` | 已写明考核流失不能当正式数 | 保留。回答模板仍是旧三句，开发时改成考核类只给现状和口径 |
| S2、S3、S6、S7 回答模板 | 仍是结论、表格、一句追问 | 开发时改成按问题类型，不套四层全文 |

预计算列继续禁止重算：毛利率、复购率、流失率、客流转化率、投入产出比。

预测、库存采购、线上订单明细、逐笔券和停车、超市业态，继续拒绝。

## 和数据准备的顺序

1. 先完成 [第一步-枚举与问数范围.md](第一步-枚举与问数范围.md)：三张 S1 表 `in_scope = 1`，枚举取值回填。
2. 再按本手册改技能回答（上表）。
3. 然后做 S1 验收问法对 `bg-data` 对答案。
4. 枚举签字之后，才把新老、高端、客群桥写进原因层。
