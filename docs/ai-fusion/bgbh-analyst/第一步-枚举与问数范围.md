# 第一步：枚举取值与 S1 问数范围

> 2026-10-17 开始。对应 [评估.md](评估.md) 第 1 项。不依赖枚举的回答规则已经落进技能；本页的取值回填之前，不要把新老、高端、经营模式编码写进过滤条件。S5 考核仍不能当正式数。
> 本环境没有百购 Doris 的查询账号，下面的 SQL 需要在 `bg-data` 和 MIS 库上执行后，把结果贴回表里。

两段分开做。先确认三张表已纳入问数，再核对会改变数字含义的存储值。

## 1. S1 三张表是否已纳入问数

在 **MIS 平台库**（`iqd_connection` / `iqd_catalog_item`）执行。项目名是 `bg-data`。

```sql
SELECT c.id AS connection_id,
       c.name,
       c.enabled,
       i.kind,
       i.item_key,
       i.display_name,
       i.in_scope
FROM iqd_connection c
LEFT JOIN iqd_catalog_item i
  ON i.connection_id = c.id
 AND (
      i.item_key LIKE '%ads_trd_mall_sale_d_df%'
   OR i.item_key LIKE '%ads_mall_trd_hall_sale_h_last_year_df%'
   OR i.item_key LIKE '%ads_csmr_store_brand_whole_sale_df%'
 )
WHERE c.name = 'bg-data';
```

表级键形如 `{数据源}.{schema}.{表名}`，模型键形如 `mdl:model:{名}`。`in_scope = 1` 才算纳入问数。导入模型默认是 0。

| 表 | 问数里有没有这项 | in_scope | 备注 |
|----|------------------|----------|------|
| ads_trd_mall_sale_d_df | 待查 | 待查 | 经营日报主表 |
| ads_mall_trd_hall_sale_h_last_year_df | 待查 | 待查 | 去年同期小时 |
| ads_csmr_store_brand_whole_sale_df | 待查 | 待查 | 坪效、品牌经营 |

没有记录，或 `in_scope` 不是 1：在问数项目 `bg-data` 里把该表纳入问数范围后再继续。不要为了这一步去改技能。

## 2. 枚举：先看列在不在，再取 distinct

在 **bg-data 对应的 Doris** 执行，只读。库名用该项目里的 database，SQL 不写死库名。

先看这三张 S1 表里，口径相关的列实际叫什么：

```sql
SELECT table_name, column_name, column_type, column_comment
FROM information_schema.columns
WHERE table_name IN (
  'ads_trd_mall_sale_d_df',
  'ads_mall_trd_hall_sale_h_last_year_df',
  'ads_csmr_store_brand_whole_sale_df'
)
AND (
     column_name LIKE '%day_type%'
  OR column_name LIKE '%date_type%'
  OR column_name LIKE '%operate_mode%'
  OR column_name LIKE '%stats_period%'
  OR column_name LIKE '%hol_name%'
  OR column_name LIKE '%channel%'
)
ORDER BY table_name, column_name;
```

列存在后，对每一列做（把库名和列名换成上一步的结果）：

```sql
SELECT `{列名}` AS val, COUNT(*) AS cnt
FROM `{库}`.`{表}`
GROUP BY `{列名}`
ORDER BY cnt DESC;
```

S1 试点至少要钉死这些含义。文档里的写法只是推断，存储值以查询为准。

| 表 | 列 | 文档推断 | 库中实际取值 | 是否签字 |
|----|----|----------|--------------|----------|
| ads_trd_mall_sale_d_df | operate_mode | 0 经销 / 1 代销 / 3 联营 / 5 百货租赁 / 6 租赁 / 14 临时场地 / 15 多经 / 18 写字楼 | 待查 | 否 |
| ads_trd_mall_sale_d_df | day_type 或 date_type | 周末、节假日、平时；也可能是工作日/周末/节假日 | 待查 | 否 |
| ads_mall_trd_hall_sale_h_last_year_df | 日期类别列 | 同上 | 待查 | 否 |
| ads_csmr_store_brand_whole_sale_df | stats_period（若有） | 日/月/季/年或近 N 月 | 待查 | 否 |

下面这些不在 S1 三张表上，但会挡住后面的新老会员、高端和流失。同一次把 distinct 做掉，避免做完 S1 又停一次。

```sql
SELECT table_name, column_name
FROM information_schema.columns
WHERE table_name IN (
  'ads_trd_store_new_old_mbr_sale_df',
  'ads_csmr_store_high_mbr_info_df',
  'ads_trd_mbr_sale_ord_d_df',
  'ads_csmr_store_csmr_tag_df'
)
AND (
     column_name IN ('mbr_new_old', 'high_mbr_range', 'stats_period', 'is_mbr', 'is_gold_card', 'is_fans', 'is_stealer')
  OR column_name LIKE 'whet_%'
)
ORDER BY table_name, column_name;
```

| 列 | 用在哪 | 文档推断 | 库中实际取值 | 是否签字 |
|----|--------|----------|--------------|----------|
| mbr_new_old | 新老会员销售 | 新会员/老会员，存储值未知 | 待查 | 否 |
| high_mbr_range | 高端会员、流失 | 1%、2%–5%、6%–10%、11%–20%、21%–50% | 待查 | 否 |
| stats_period | 各周期表 | day/month 或「近一年」等中文 | 待查 | 否 |
| is_mbr / is_gold_card / is_fans | 标签 | 业务定义有，存储可能是 Y/N 或 1/0 | 待查 | 否 |
| whet_* | 订单上的新客标记 | 是/否，或 1/0 | 待查 | 否 |

`ctbtn_amt` 与 `actual_ctbtn_amt` 的口径差、各表 T+几，仍要数据组书面说明。本步只登记 distinct，不改技能。
