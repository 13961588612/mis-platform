# 分阶段上线实施计划 v1.0

> 前提（阻塞项，P0 前必须闭环）：02 文件第 5 节《待确认清单》1-5 项——枚举值、口径、分区、数据延迟。
> 每阶段"成功标准"即验收口径，达不到不进下一阶段。

---

## Phase 0：数据就绪核查（约 1 周）

| 事项 | 动作 | 验证方式 |
|------|------|----------|
| 枚举值盘点 | 对 stats_period/mbr_new_old/is_mbr/whet_*/day_type/high_mbr_range 跑 distinct | 输出枚举字典表，数据组签字（书面留痕） |
| 口径确认 | 客单价、贡献金额vs实际贡献价值、高端区间阈值 | 邮件确认口径文档 |
| 数据延迟 | 各 ADS 表 T+? 、分区键 | 调度平台截图 |
| DIM/DWS 补档 | 12+2 张表字段明细（图片转文字） | 建模同学提供源文档 |
| 建联调账号 | wrenai 对接库只读账号（ADS+DIM schema 权限） | 权限单 |

## Phase 1：单域 POC（约 2 周）—— 经营日报 S1

- **范围**：wrenai 挂 3 张表（mall_sale / store_new_old_mbr / cst_flow_hour），S1 Skill 上线
- **样本**：S1 全部 + S2-A/B 问题，30-50 条训练对，全部跑通验证
- **成功标准**：50 条抽测问法，取数正确率 ≥90%，P95 响应 < 10s
- **验收人**：数据组 1 人 + 运营 1 人，双签

## Phase 2：会员主题扩展（约 2 周）—— S2 + S5

- 增挂：store_mbr_sale / high_mbr_info / mbr_hall_sale_d / drain_analysis / store_mbr_drain / drain_assess
- Skills：S2、S5 上线（S5 含追问链 C→D）
- **成功标准**：S5 流失清单类问题 100% 出数正确（涉及考核，口径零容忍）；Skill 路由准确率 ≥90%

## Phase 3：品牌与关联（约 2 周）—— S3 + S4

- 增挂：brand_new_mbr×2 / brand_trd / brand_frq / brand_attri / whole_sale / 关联4表
- **风险点**：关联4表为"TopN 宽表"（品牌名在列值而非维度），问法必须引导为"XX品牌的关联品牌Top5"，样本对要重点覆盖，否则 LLM 极易理解错表结构
- **成功标准**：S4 关联度类问题正确率 ≥85%

## Phase 4：剩余主题 + 运营化（约 2 周）—— S6 + S7 + 全量

- 增挂：parking / wechat×2 / store_csmr_tag / mbr_store_input / drain 剩余3表 / mall 小时表
- 运营机制上线：每周未命中问题复盘、样本库版本管理、口径变更双文件同步（01/02 体系文档 + wrenai 配置）

## 回退方案

| 场景 | 动作 |
|------|------|
| 某 Skill 正确率不达标 | 单独下线该 Skill（OpenHarness 路由层关闭），其余 Skill 不受影响；问题转人工 |
| wrenai 生成错误造成业务误导 | 智能体侧结果校验层拦截 + 全量审计当次会话；必要时回滚到上一版样本库 |
| 上游 ADS 表口径变更 | 触发《待确认清单》复盘流程，相关 Skill 挂"数据核对中"提示 |

## 当期风险登记

| 风险 | 等级 | 应对 |
|------|------|------|
| 枚举/口径迟迟未书面确认 | 🔴 高 | P0 设为硬门槛；先拿口头答复也要邮件追认 |
| 关联4表宽表结构 LLM 理解困难 | 🟡 中 | 重样本覆盖 + 表描述写清"TopN在列值" |
| DIM/DWS 明细缺失导致维度问题答不了 | 🟡 中 | Phase 1 前先补档；缺失维度问法先入拒答清单 |
| 金额类问题单位/口径混淆（含券/去券/去税） | 🟡 中 | Instructions 口径规则 + 样本中刻意覆盖三种说法 |
| 多门店混合口径（商户 business vs 供货商 supplier） | 🟢 低 | 术语表锁定 + 样本覆盖 |
