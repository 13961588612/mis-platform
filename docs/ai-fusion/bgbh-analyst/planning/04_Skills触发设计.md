# 智能体 Skills 触发设计（OpenHarness ↔ WrenAI 0.13）v1.0

> ✅ **本设计的完整 Skill 定义已产出，见 `skills/` 目录**：`00_总控路由_SKILL.md`（路由/分流/拒答/校验/兜底/全局指令）+ `S1~S7` 七个业务Skill（触发词/槽位/表白名单/改写模板/回答模板/追问链/降级/验收用例，均带YAML frontmatter）+ `README.md`（注册映射与变更纪律）。本文件为设计说明，skills/ 为可注册内容，两者同步维护。

> 架构：用户 → OpenHarness 智能体（意图识别/槽位抽取/Skill 路由）→ 改写为规范问句 → WrenAI（Text-to-SQL）→ 结果回传 → 智能体组织回答（表格+一句结论+可下钻建议）。
> 设计原则：**Skill 先锁主题域，再调问数**；每个 Skill 是一个"分析场景包"= 触发词 + 槽位 + 可用表白名单 + 问句改写模板 + 回答模板。

## 2. 单 Skill 定义模板（以 S5 会员流失为例）

```
Skill: S5 会员流失
触发:
  强触发: 流失、沉睡、休眠、唤醒名单、流失预警、流失率、流失去向
  弱触发（需含时间/门店槽位才路由）: 多久没来、不消费
不触发（转通用问答/拒答）: "为什么会流失"（归因分析，不下SQL）
槽位:
  时间: 默认=最近快照日(snapshot_date max)
  门店: 必填，缺省时追问"请告诉我哪个门店？"（流失类问题全店跑量太大）
  对象: 会员整体 | 某品牌 | 某卡类型 | 高端区间
  流失周期: 默认全部周期
问句改写模板:
  "【S5】{时间} {门店} {对象}的{流失指标}" → 例："昨天 北京路店 高端会员 各流失周期流失人数和流失率"
回答模板:
  1) 结论先行: 一句话数字（例：北京路店昨日高端会员流失37人，流失率4.2%）
  2) 表格: TopN 明细
  3) 主动追问建议: "要不要看流失会员去向Top10？" → 路由 S5-D
降级:
  - 表未上线/查询失败 → "流失数据当前不可用，已记录" + 转人工
  - 用户问归因 → 调用分析型回答（规则话术），不编数字
```

其余 Skill 按同模板填写（首批实现 S1/S2/S5 三个，模板最全）。

## 3. 路由与冲突规则

1. **一词多义仲裁**："销售"出现在 S1（整体）/S2（会员销售）/S3（品牌销售）→ 看共现词：带"会员"→S2；带"品牌/新客"→S3；否则 S1。
2. **多 Skill 串联**：S5-D（去向）依赖 S5-C（品牌流失）结果 → 智能体上下文传递 brand_id，不依赖用户复述。
3. **超出数据边界**：问"库存/采购/线上电商"（DWD 有合同/商品但无库存主题）→ 明确答复"当前数据未覆盖，建议联系数据组"，**不允许让 wrenai 硬编 SQL**。
4. **分析型 vs 取数型**：所有 Skill 共用分流器——含"为什么/建议/预测/怎么办"→ 分析链路（基于取数结果+规则话术）；否则取数链路。

## 4. OpenHarness ↔ WrenAI 交互约定

| 项 | 约定 |
|----|------|
| 请求 | 改写后问句（含已确认槽位）+ skill_id → wrenai ask API |
| 上下文注入 | skill 对应 business terms 子集 + instructions 已全局生效，skill 不再重复注入 |
| 结果校验 | 智能体侧做三层校验：①空结果→换时间口径重问一次；②金额量级异常（|值|>历史P99×3）→ 标记"结果存疑"；③SQL 涉及白名单外表→ 拒答 |
| 失败兜底 | 两次失败 → 返回"这个问题我暂时没查准，已把原始问题转给数据组"，记录未命中日志 |
| 追问 | wrenai 返回 follow-up 候选时，智能体用 skill 追问建议覆盖，保持场景闭环 |

## 5. 上线验收标准（Skill 层）

- 触发准确率：抽 50 条真实问法，Skill 路由正确 ≥90%
- 槽位追问：缺必填槽位时 100% 追问而非瞎查
- 取数正确率：每 Skill 抽 20 条已验证问题，SQL 结果与人工核对一致 ≥95%
- 拒答合规率：越界问题 100% 走拒答话术，零编造型回答
