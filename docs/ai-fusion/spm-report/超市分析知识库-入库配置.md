# 超市经营口径库：怎么规划、怎么入库

给**知识库管理员**用。用户问答正文见 [超市分析知识库.md](超市分析知识库.md)，不要把本文上传给业务用户检索。

---

## 1. 这份库解决什么问题？

超市助手取数、出表靠经营系统；**口径、术语、能问什么、为什么没有今天**，要靠知识库检索补上。

用户典型问法（应用命中测试）：

- 为什么查不到今天？
- 日报为什么不跟昨天比？
- 前台毛利和综合毛利有什么区别？
- 总折扣是不是就是促销打折？
- 什么是利润品 / A 类？
- 日报为什么没有库存？

命中后应引用**完整口径段**，而不是半截表格。

「这个系统能帮我看什么」这种问法**单靠检索不够**。知识块里必须带「超市经营」；对话还要落在超市助手（或只检索「超市经营口径」这一库）。泛问「这个系统」且没有店名/日报/毛利等词时，可能进制度库或其它助手。用户更稳的问法：带「超市」「门店经营」「日报」等。

---

## 2. RAG 文档应具备什么？

面向「使用中有疑问再问」的口径库，正文需要：

| 要求 | 做法 |
|------|------|
| 用户语言 | 用「你怎么问、表上怎么读」，不写接口名、技能名、字段名、权限码 |
| 一问一段 | 每个二级标题就是一个可独立回答的问题；切块后不依赖「见上文」 |
| 术语自洽 | 同一概念全文只用一个说法（如始终「去券销售」，不要混「净销售」） |
| 边界写清 | 明确「现在没有」：今天、采购、单品 ABC、日报无库存 |
| 对比规则可检索 | T+1、上周同一天、上一业务周/月 各自成节 |
| 表格短 | 单表能放进一个切片；超长表拆到对应问题下 |
| 少交叉引用 | 不要「见第 5.2 节」；必要处把结论再写一遍 |

不适合进本库的：开发手册、Skill 全文、接口清单、部署说明。那些应另库或根本不入库。

## 3. 怎么规划（建议只建一个库）

当前篇幅适合 **一个分类 + 一个知识库 + 一篇主文档**。

| 项 | 建议 |
|----|------|
| 分类 | 「超市」（已有则挂其下，不要再建同名根分类） |
| 知识库名称 | 超市经营口径 |
| 密级 | `internal`（内部同事；不要 public） |
| 文档 | 只上传 `超市分析知识库.md`（用户问答稿） |
| 不要上传 | 本入库配置、Skills、架构文档 |
| 以后变长 | 再按主题拆成「时间与对比」「指标口径」「品类 ABC」多文件，仍放同一库 |

切片按二级标题切：库设置里分隔符写成 **`` `##` ``**（带反引号），切片大小约 **320**。不要用 `---`，也不要只填没有反引号的 `##`。每个标题带「超市经营」，切出来的块不依赖文首总标题。

---

## 4. 建库与 RAG 设置（对照管理台「知识库详情 → RAG 设置」）

引擎按现网 **RAGFlow v0.27.2**：切片参数写在解析配置顶层，不要再包一层 ext（mis-kb 发版后生效）。

### 4.1 建库期（解析 / 切片）

这份中文问答 + 小表，优先「切得准」而不是「块很大」。

| 设置 | 建议值 | 原因 |
|------|--------|------|
| 切片方法 | **通用（naive）** | Markdown 说明文 |
| 切片大小 | **256～400**（建议 **320**） | 见下方「为什么会变成一整块」 |
| 分隔符 | 填 **`` `##` ``**（两个 # 外面加反引号） | 见下方；不要只填 `##`，也不要用 `---` |
| 重叠 | **0～10%**（能下发再用；下发失败则保持 0） | 口径文重复少，重叠大会造成两块抢同一问 |
| 页码索引 | 开或关影响都不大 | 无 PDF 页码；Markdown 可关 |
| 图像/表格上下文 | 默认即可 | 表已嵌在对应问题下 |
| 自动关键字 | **8** | 给「前台毛利」「T+1」「利润品」等补检索词 |
| 自动问题 | **5** | 引擎为每块生成「什么是…」类问句，贴合用户问法 |
| RAPTOR 摘要树 | **关** | 文档短，开树成本高、对 FAQ 增益小 |
| 知识图谱 | **关** | 无实体关系抽取需求 |

向量模型与平台中文模型保持一致（常见为 bge 一类），建库后不要中途换模型，否则要整库重解析。

**`##` 不会被解析器删掉。** 标题行会留在正文里。整篇变成一块，通常是下面两步叠在一起，不是标题被剔除。

1. **多字符分隔符必须用反引号包起来。** RAGFlow 只把 `` `##` `` 当成「按二级标题切开」。只填 `##` 时，引擎当两个单字符 `#`，切完仍是碎句，下一步会再拼回去。
2. **切开之后还会按「切片大小」合并。** 默认 2048 token，这份口径文全文往往不到 2048，所以即使用换行切开，也会 **全部并成一块**。要一块一个问题，切片大小必须小于两节相加（约 320），分隔符用 `` `##` ``。改完必须 **重解析或重传**。

核对：文档切片列表应接近正文里 `##` 的条数（十几个），而不是 1。

### 4.2 检索期（问答命中）

| 设置 | 建议值 | 原因 |
|------|--------|------|
| 检索方式 | **混合（hybrid）** | 既要「T+1」「ABC」这种关键词，也要「日报为啥不比昨天」这种语义 |
| 混合时向量权重 | **0.3～0.5** | 口径问答略偏关键词更稳；可按命中测试再调 |
| 召回条数 topK | **5** | 单问通常 1～2 段就够；过大易把无关节塞进提示 |
| 相似度阈值 | **0.2～0.3** | 过低会召回整篇；过高「查不到今天」类口语问会空 |
| 重排 | 平台已配重排模型则可开 | 块少时收益一般；模型未配不要开 |
| 空结果 | 按平台默认「如实无结果」 | 不要在无命中时编口径 |

### 4.3 上传与解析

1. 分类「超市」下新建库「超市经营口径」，密级内部。
2. 按上表保存 RAG 设置（新建抽屉若只有基础项，到详情页补切片方法、分隔符、自动关键字/问题）。
3. 上传 `超市分析知识库.md`。
4. 等解析完成（未开始/失败则点重解析）。
5. 不要用「改切片却不重解析」——v0.27 改文档配置后必须再解析才生效。

## 5. 入库后怎么验收？

在命中测试里用下面这些问句，每条都应打到对应小节，而不是整篇或无关章：

1. 超市经营分析能帮我看什么？ / 为什么没有今天的数据？
2. 日报对比的是昨天吗？
3. 客单价的单位是万元还是元？
4. 前台毛利和综合毛利有什么区别？
5. 损耗是不是吃掉了毛利？
6. 总折扣和促销打折是一回事吗？
7. 日报能看库存吗？
8. 什么是利润品？什么是 A 类？
9. 周报默认跟谁比？
10. 生鲜是怎么圈出来的？

若「ABC」命中到促销节：把切片调小或确认分隔符是 `##`。  
若「查不到今天」召不回：略降阈值，或看自动问题是否已生成近义问句。

口径变更时：先改正文，再在同一文档上重解析，不必新建库。
