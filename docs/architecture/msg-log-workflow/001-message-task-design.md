# 统一消息中心与代办任务体系设计

> 版本: v1.0  |  日期: 2026-09-30  |  状态: 设计方案

---

## 一、设计目标

为 MIS 平台建立**统一的消息 + 代办事件中心**，满足以下核心需求：

1. **搜索**: 全局全文检索，按类型/状态/来源/时间多维筛选
2. **代办+消息双轨并行**: 消息可以独立存在，也可以与代办绑定；无关联的纯消息也能正常展示
3. **统一交互界面**: 在管理后台提供一个统一的收件箱入口，支持标记已读、处理、完成等通用操作

---

## 二、核心概念模型

### 2.1 三实体关系

``text
+-------------------+     +--------------------+     +-------------------+
|  Message (消息)    |     |   BizReference     |     |  Task (代办任务)  |
|                  |-----|                    |-----|
| * 接收者          |     | * message_id       |     | * 任务类型         |
| * 标题/摘要       |     | * task_id          |     | * 目标实体         |
| * 内容/附件       |     | * biz_type         |     | * 审批人/执行人    |
| * 发送时间        |     | * biz_ref_id       |     | * 审批结果         |
| * 已读状态        |     | * biz_status       |     | * 截止时间         |
|                  |     | * created_at       |     | * 优先级           |
+-------------------+     +--------------------+     +-------------------+
``

**关系说明:**
- 一条 Message 可以通过 BizReference 关联零个或一个 Task
- 关联时：消息作为代办的通知载体，代办是消息的业务动作延伸
- 不关联时：消息纯粹用于信息同步（如系统公告、审批通过通知）
- 多个消息可以关联到同一个 Task（如催办通知链）
