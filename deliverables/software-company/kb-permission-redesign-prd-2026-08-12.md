- **作者**：许清楚（软件产品经理）

- **类型**：**增量 PRD**（默认简单 PRD：产品目标 + 用户故事 + 需求池 P0/P1 + UI 变更说明 + 验收标准 + 待确认问题）
- **状态**：待架构师（高见远）技术设计 → 工程师（寇豆码）实现 → QA（严过关）验收
- **上游权威输入**：`docs/analysis/kb-permission-redesign-review-2026-08-12.md`（架构评审，已拍板 D1~D7 关键决策，本 PRD 以其结论为准，不推翻）

## 1. 产品目标

以「分类管辖 → 知识库管理」这一后端已有的合成语义（`NodeAdminResolver.hasLibraryManage`）为基准，通过补服务层数据范围闸门、接口数据面收敛与前端「可管理 / 可见」双口径过滤，实现「**分类管理员自动获得其分类下知识库 / 文档的管理权限**（建库、给库加文档、改 RAG 设置、归档等）」，让授权路径从「① 设分类权限 → ② 建库 → ③ 再授库管理权限」三步收敛为一步，同时把「权限」页收敛为只控制知识搜索数据范围的「搜索权限」页；全程**零数据迁移、零检索鉴权改动**，保证存量 `manage/acl` 授权兼容生效不放大权限。

## 2. 用户故事（分类管理员视角）

| # | 用户故事 | 验收语义 |
|---|---|---|
| US-1 | 作为**财务分类管理员**，我想在「知识库」页新建知识库时只看到我管辖的分类（含子分类），建完后**立即**能上传文档、改 RAG 设置、归档，这样我不需要再找全局管理员额外授予知识库管理权限。 | 分类下拉只列管辖分类；建库后 `hasLibraryManage=true`，文档写操作不报 40311。 |
| US-2 | 作为**财务分类管理员**，我想在「文档」页的库选择器里只看到我能管理的知识库，这样我不会误选一个只能读的库然后报「无管理权限」。 | 文档页组合框只显示可管理库；无库时给出空态文案而非空白。 |
| US-3 | 作为**财务分类管理员**，我想在「搜索权限」页为我管理的知识库按用户 / 角色 / 部门授予**只读（read）**权限，这样我能控制谁能搜索到该库数据，且页面上只提供只读这一种入口，避免误授管理 / 授权类权限。 | 页面标题为「搜索权限」；授权动作下拉只有 read；库列表口径为「可管理的库」。 |
| US-4 | 作为**财务分类管理员**，当我的分类下暂无知识库时，我想看到明确的空态提示（而非空白或报错），这样我知道当前没有可管理的对象而不是系统坏了。 | 管理页空态文案明确（如「您暂无管辖的分类 / 知识库，请联系管理员」）。 |

## 3. 需求池

> 优先级：**P0 = 必须（本期交付边界）**；**P1 = 应当（本期交付边界）**；范围外见 §6。
> 关键决策引用（来自架构评审，本 PRD 直接遵守）：**D1** 服务层闸门优先；**D2** ACL 零迁移「UI 收敛 + 后端兼容」；**D3** UI 双口径（可管理 / 可见）；**D4** 接口收敛；**D5** 权限页改名「搜索权限」；**D6** 固化继承语义；**D7** 检索零影响。

### 3.1 P0（必须）

| 编号 | 需求 | 产品口径 | 验收判据（可度量） |
|---|---|---|---|
| **KBP-01** | **服务层数据范围闸门（D1）**：`KbLibraryService.create/update/delete` + `RagSettingsService.save` 补数据范围校验，并把 `userId` 从 Controller 贯通进 Service（现签名未带）。 | create=校验目标分类在管辖内（`assertNodeManage`，消除「在非管辖分类下建库」根因）；update/delete/save=校验 `hasLibraryManage`。功能权限码只控制入口，数据范围一律由 mis-kb 二次裁定（双闸门）。 | ① 持有 `kb:library:add` 但目标分类不在管辖内的用户直连 API 建库 → 403（对应业务码 40311 语义）；② 非 `hasLibraryManage` 用户直连 update/delete/RAG save → 403；③ 分类管理员对自管库的建 / 改 / 删 / RAG 设置操作全部放行（回归零差异）；④ mis-kb 单测覆盖上述正反分支。 |
| **KBP-02** | **接口数据面收敛（D4）**：新增 `GET /kb/libraries?scope=manageable\|visible`（或 `manageable-library-ids`），前端不再拉全量本地过滤。 | 数据面收敛优先于前端本地过滤，安全侧更好；默认（不带 scope）行为与现有一致以兼容存量调用。 | ① `scope=manageable` 只返回 `hasLibraryManage` 的库；② `scope=visible` 返回可见库（public∧enabled ∪ ACL read − disabled，与 `KbVisibilityService` 口径一致）；③ 不带 scope 返回现状全量（兼容）；④ 前端不再依赖全量列表本地过滤可管理的库。 |
| **KBP-03** | **知识库管理页按「可管理」过滤（D3）**：`kb-library-page` 左侧分类树与「新增知识库」分类下拉按管辖过滤（含子树），空态提示。 | 管理界面一律用「可管理」口径；分类树保留「全部 / 仅管辖」切换（复用分类管理页 `onlyManageable` 先例）。 | ① 分类下拉只列当前用户管辖的分类（子树）；② 非管辖分类不出现、不可选作建库目标；③ 非管理员进页面看到空态文案而非空白；④ 「仅管辖」开关生效且与后端 `scope` 口径一致。 |
| **KBP-04** | **文档管理页按「可管理」过滤（D3）**：`kb-document-page` 库组合框只显示可管理库，空态提示。 | 文档操作（上传 / 启停 / 重解析 / 删除）的前提是库可管理，组合框口径必须与 `hasLibraryManage` 一致，避免「选得到但操作不了」。 | ① 组合框只显示可管理库；② 无可管理库时给出空态文案；③ 保留 `KbLibraryCombobox` 现有同名 / 路径提示逻辑（R8 不回归）；④ 选中库后文档操作全程不出现「无管理权限」误报。 |
| **KBP-05** | **权限页改名「搜索权限」（D5）**：路由 /kb/permissions 页面与导航标题「权限」→「搜索权限」，action 只保留 read，可见性规则 / 说明文案更新，库列表口径改为「可管理的库」。 | 该页只承载「控制搜索数据范围」的 read 授权语义；manage 由分类管辖继承（本页不再提供入口），acl 授权入口下线。 | ① 导航标题（`kb-nav.ts` L19）、页面标题、面包屑均改为「搜索权限」；② 授权动作下拉只出现 read（`KB_ACL_ACTION_OPTIONS` 裁剪或页面过滤）；③ 库列表口径 =「可管理的库」（传 `scope=manageable`）；④ 说明文案写明「只读用于控制知识搜索数据范围；管理权限随分类管辖自动获得」；⑤ 存量 manage/acl 授权行仍展示并标注「存量授权（兼容生效）」，允许撤销、不可新增（产品默认，见 Q1）。 |
| **KBP-06** | **固化继承语义（D6）**：子树继承 + 多主体并集 + 全局管理员短路，与 `NodeAdminResolver` 现状一致，禁止改动。 | 设计文档与验收标准显式固化该语义，防止后续被误改成交集 / 仅限直接子级引发权限事故。 | ① 单测覆盖三个分支：授权节点整棵子树可管理；user∪role∪dept 多主体任一命中即放行（并集）；全局管理员角色码短路；② 与现状 `NodeAdminResolver` 行为比对零差异。 |
| **KBP-07** | **ACL 零迁移「UI 收敛 + 后端兼容」（D2）**：`AclAction` 枚举与 `kb_acl` 表结构不动；存量 `manage/acl` 授权行保留兼容生效；UI 只保留 read 入口；提供一次性只读清单供运营清理。 | **不做自动数据迁移（防权限放大）**：库级授权与节点级管辖粒度不同，迁移会放大权限。存量行以「API 兼容生效 + UI 无新增入口 + 只读清单」三种方式收敛。 | ① 无 DDL 迁移（本期零迁移脚本）；② 存量 manage/acl 行在 API 层仍生效（授权后 `hasLibraryManage` 仍为 true）；③ 新增授权接口只允许 action=read；④ 只读清单端点可查「哪些库、哪些主体仍有 manage/acl 授权」（P1 落地）。 |

## 4. UI 变更说明

### 4.1 知识库管理页 `kb-library-page.tsx`

- **分类树**：默认按「可管理」口径过滤（管辖子树），保留「全部 / 仅管辖」切换。
- **新增 / 编辑抽屉**：「所属分类」下拉只列当前用户管辖的分类（含子树）；选择非管辖分类即不可建库（服务层同步兜底，KBP-01）。
- **空态**：非管理员进入时显示「您暂无管辖的分类 / 知识库，请联系管理员」。
- **口径说明**：页面顶部或空态旁文案注明「此处仅列出您可管理的知识库」。

### 4.2 文档管理页 `kb-document-page.tsx`

- **库组合框**（`KbLibraryCombobox`）：传 `scope=manageable`，只显示可管理库。
- **空态**：无可管理库时显示「您暂无管理的知识库，请联系管理员」。
- 保留同名 / 路径强提示逻辑（R8）。

### 4.3 搜索权限页 `kb-permission-page.tsx`（原「权限」页）

- **标题**：页面标题「知识库权限」→「搜索权限」；面包屑「权限」→「搜索权限」；导航（`kb-nav.ts` L19）同步改。
- **授权动作**：下拉只保留 read（`KB_ACL_ACTION_OPTIONS` 裁剪为 read 或页面过滤）。
- **库列表口径**：组合框传 `scope=manageable`，只列「可管理的库」。
- **说明文案**：可见性规则 Alert 保留并补充「只读用于控制知识搜索数据范围；管理权限随分类管辖自动获得」；新增授权抽屉内的说明文案同步更新（删除「manage 用于文档与配置的写操作，acl 可再授权他人」这类与新语义冲突的描述）。
- **存量行**：manage/acl 行仍展示，标注「存量授权（兼容生效）」，可撤销、不可新增（见 Q1）。

### 4.4 导航 `kb-nav.ts`

- 标题「权限」→「搜索权限」（L19）。注意按 `kb-nav.ts` 头注释：改导航需三处同改（`kb-nav.ts`、`keep-alive-outlet.tsx` PAGE_MAP、迁移 SQL sys_menu seed），若菜单标题由迁移 SQL 提供，需一并核对。

### 4.5 问答页 `kb-qa-page.tsx` 组合框口径（P1）

- 库选择器传 `scope=visible`，只显示「可见库」；文案注明「此处列出您可见的知识库」。
- 检索 / 问答接口鉴权逻辑**零改动**（D7）。

## 6. 范围外说明（本期明确不做）

1. **存量数据迁移**：`manage/acl` 授权行**不做自动迁移**（防权限放大），仅 UI 收敛 + 后端兼容 + 只读清单（D2）。
2. **检索鉴权改动**：检索 / 问答接口鉴权逻辑不动（本就只认 read），零影响（D7）。
3. **文档级权限**：文档无独立权限，完全随库（维持现状）。
4. **`AclAction` 枚举与 `kb_acl` 表结构变更**：枚举与表结构不动（D2）。
5. **功能权限码体系重构 / 新增权限码**：全部复用既有 `kb:*` 权限码，继承语义不需要新增权限码（评审 §B.3）。
