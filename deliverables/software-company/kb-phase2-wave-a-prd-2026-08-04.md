### 1.1 原始需求复述

二期扩展第一波（Wave A 质量线）要交付四件事：

1. **A1 混合检索打磨** —— 库级可配 `retrievalMethod` 与向量/关键字权重，并**真正下发到引擎检索调用**；引擎能力显式声明 `hybrid`。
2. **A2 Rerank** —— 补齐重排模型 ID 配置来源；无模型时 UI 禁用、后端强制关闭并给友好提示。
3. **A3 切片与空结果（L-08 齐套）** —— 切片参数与空结果策略在 MIS 可配、可同步引擎、**可真正生效**；改动后提示重解析并提供单文档重解析。
4. **A4 命中测试 Q-04** —— 管理侧「选库 → 提问 → 只 retrieve → 看 chunk/score/文档名」的调参闭环，链路不经 mis-rag/LLM。

**不在本次范围：** Wave B（GraphRAG PoC、`useKnowledgeGraph`、`kgBuildStatus`、Neo4j）、Wave C（RAPTOR / TOC 增强 / Parent-Child）。

> 以下为本人逐文件核查结果，用于把「规划文档里的缺口」校准成「代码里的真实缺口」，请架构师以此为准。

| 能力项 | 代码现状 | 真实缺口 | 归属 |
|--------|----------|----------|------|
| 检索方式配置 | `RagSettings.retrievalMethod`（vector/keyword/hybrid，默认 hybrid）已有；前端库列表页与详情页均有下拉 | 无字段缺口 | — |
| 向量/关键字权重 | **无** `vectorSimilarityWeight` 字段；`RagflowClient.updateDatasetSettings()` 未下发 `vector_similarity_weight` | 字段 + 下发 + UI 全缺 | **A1** |
| 检索调用参数 | `RetrieveQuery` 仅 `question/libraryIds/topK/threshold`；`KbRetrieveService.retrieve()` **完全没有读取库级 `RagSettings`**；`RagflowClient.retrieve()` 请求体只有 `question/dataset_ids/page_size/similarity_threshold` | **最严重缺陷：库设置的检索方式/权重/rerank 从未参与实际检索**，只在建库/改库时写进 dataset 设置 | **A1** |
| 引擎能力声明 | `RagflowAdapter.capabilities()` 返回 `["rerank","metadata_filter","replace"]`；`EngineCapabilities` 无 hybrid 布尔位 | 未声明 `hybrid` | **A1** |
| noop 降级 | `NoopAdapter.capabilities()` 返回 `unsupported()`，`retrieve()` 返回空列表 | hybrid 降级行为未成文、无日志 | **A1** |
| Rerank | `RagSettings.rerank` 已有，`updateDatasetSettings` 下发 `rerank` 布尔；前端按 `capabilities.rerankSupported` 灰化开关 | **无 `rerankModelId`**；`RagflowProperties` 只有 `type/baseUrl/apiKey`，无 `rerank-model-id`；检索侧未下发 `rerank_id` | **A2** |
| 切片参数 UI | **已具备**：`kb-library-detail-page.tsx`「RAG 设置」Tab 已有 `chunkMethod` / `chunkTokenNum` / `separator` / `emptyResultStrategy` 全部控件与静态提示 | UI 主体不需重建，仅需补权重滑条与文案修补 | **A3（缩量）** |
| 单文档重解析 | 前端 `kb-document-table.tsx` → BFF `POST /libraries/{lib}/documents/{id}/reparse` → `DocumentController.reparse()` **链路已通** | **`RagflowAdapter.reparseDocument()` 是空方法（P0 留空）**，点了不生效 | **A3** |
| 空结果策略 | `EmptyResultStrategy` 枚举 = `SUGGEST` / `EMPTY` / `TRANSFER`，可配置、可校验、可持久化 | **全链路无任何消费点**，问答侧未按策略分支，属「配了不生效」 | **A3** |

## 3. 产品定义

### 3.1 产品目标（3 个正交目标）

Wave A 要解决的是同一个根问题的三个面：**知识库检索质量目前既"调不动"也"看不见"**。

| # | 目标 | 说明 | 衡量口径 |
|---|------|------|----------|
| **G1 检索质量可控** | 混合检索（关键字 + 语义）与重排在库级可配，且**配置真正作用于每一次检索调用**，不再停留在建库参数 | 任一库改 `retrievalMethod` / 权重 / rerank 后，下一次问答与命中测试的召回结果可观测到差异 |
| **G2 运营可自助调参** | 切片方案、切片长度、分隔符、空结果策略、召回参数全部在 MIS 知识 APP 内配置并同步引擎，业务/运营**无需登录 RAGFlow 控制台** | L-08 页面覆盖 §3.5 表中标注「MIS 库设置」的全部配置项；改动后有明确的"需重解析"引导且重解析真实生效 |
| **G3 调参有闭环反馈** | 提供不经 LLM 的命中测试，让调参者在秒级看到"这套参数召回了什么" | 命中测试可选库、可临时覆盖参数、可展示 chunk 文本 + score + 文档名；单次响应 P95 < 3s |

> 三个目标正交：G1 是**能力打通**（后端链路），G2 是**入口收敛**（前端配置面），G3 是**验证手段**（观测面）。缺任一个，另两个都无法验收。

### 3.2 用户故事

| # | 角色 | 用户故事 | 对应 |
|---|------|----------|------|

| **US-2** | 知识库管理员 | 作为**知识库管理员**，我希望调整切片方法与切片长度后系统明确告诉我"哪些已有文档需要重新解析"并能一键重解析单个文档，以便新参数真正作用到存量文档而不是只对新上传生效 | A3 |

## 4. 需求池

> 编号规则：`WA-xx`；每条标注对应 Wave A 子项与验收标准。**验收标准以"可观测行为"描述，不描述实现方式**（实现方案由架构师定）。

### 4.1 P0（Must have —— 不做则 Wave A 不成立）

#### WA-01 · 库级向量相似度权重字段（A1）

- **描述**：`RagSettings` 增加 `vectorSimilarityWeight`（0～1 浮点），语义为「语义（向量）召回在混合排序中的权重」，仅在 `retrievalMethod = hybrid` 时生效；保存时随库设置同步到引擎 dataset 配置。
- **验收标准**：
  1. 库设置保存 `vectorSimilarityWeight = 0.5` 后，重新加载详情页显示 0.5，且引擎侧 dataset 配置同步收到该值。
  2. 取值越界（<0 或 >1）时接口返回明确的业务校验错误，不写库。
  3. 存量库该字段为空时按默认值兜底，**不需要数据回填**（与 V15 四字段同一处理口径）。
  4. `retrievalMethod ≠ hybrid` 时该字段不参与检索计算（可保存，但不下发或下发后被引擎忽略，需在文档中写明口径）。

#### WA-02 · 库级检索参数下发到实际检索调用（A1）★ 本波次最高优先级

- **描述**：打通「库设置 → 检索调用」链路。检索时须携带该库的 `retrievalMethod`、`vectorSimilarityWeight`、`rerank`（及 rerank 模型）等参数，而不是仅依赖建库时写入的 dataset 默认值。多库检索时的参数取值口径需明确定义（见待确认 Q6）。
- **背景（现状缺陷）**：`KbRetrieveService.retrieve()` 当前只用请求里的 `question/libraryIds/topK/threshold` 构造 `RetrieveQuery`，从不读取库级 `RagSettings`；`RagflowClient.retrieve()` 请求体也不含 `retrieval_method` / `vector_similarity_weight`。**这意味着 L-08 上的检索方式设置在问答链路中实际从未生效。**
- **验收标准**：
  1. 同一个库、同一个问题，把 `retrievalMethod` 从 `keyword` 改为 `vector`（或调整权重）后再次检索，**召回结果集或排序发生可观测变化**（可用命中测试页验证）。
  2. 检索调用的出参日志（DEBUG 级）可打印本次实际使用的检索方式与权重，便于排障。
  3. 问答主链路（BFF → mis-kb retrieve → mis-rag）与命中测试链路使用**同一套参数合并逻辑**，不出现两套口径。
  4. 单元测试覆盖：库级设置为 hybrid+权重 0.3 时，传给引擎客户端的参数包含对应值。

#### WA-03 · 引擎能力显式声明 hybrid + noop 降级行为（A1）

- **描述**：`EngineCapabilities` 增加 `hybrid` 能力码（RagflowAdapter 声明支持）；NoopAdapter 在库配置为 hybrid 时的行为写入明确定义（见待确认 Q5）。前端「引擎配置」页与库设置页按能力显隐/灰化。
- **验收标准**：
  1. 引擎配置页「能力清单」出现「混合检索 hybrid」能力徽标，RAGFlow 引擎下为"支持"。
  2. 引擎不声明 `hybrid` 时，库设置页的「混合检索」选项被禁用并给出原因提示（不是静默隐藏）。
  3. noop 引擎下选择 hybrid 时，按既定降级策略执行并输出 WARN 级日志（含库 ID 与被降级的原因），不抛异常中断问答。
  4. **降级原因对用户可见**：命中测试页在发生降级时回显具体原因（如"引擎不支持混合检索，已降级为向量检索"），不能只写进服务端日志。调参工具若不告知参数是否真正生效，其结论不可信。

#### WA-04 · L-08 权重滑条与 hybrid 显隐逻辑（A1）

- **描述**：库详情页「RAG 设置」Tab 中，检索方式选择 `hybrid` 时显示「语义 / 关键字权重」滑条（0～1，步长 0.05，双侧标注百分比），非 hybrid 时隐藏该滑条。产品文案统一为「混合检索 = 关键字检索 + 语义（向量）检索」。
- **验收标准**：
  1. 切换检索方式为 vector/keyword 时滑条即时隐藏；切回 hybrid 时恢复上次值。
  2. 滑条旁展示当前含义文案，如「语义 30% / 关键字 70%」。
  3. 保存后回显一致；无 `kb:library:edit` 权限时控件只读。
  4. 文案中不出现"图谱/GraphRAG"字样，避免与 Wave B 概念混淆。

#### WA-05 · Rerank 模型 ID 配置与下发（A2）

- **描述**：新增重排模型 ID 配置。配置来源优先级需拍板（见待确认 Q2），基线方案：全局 Nacos `mis.kb.engine.rerank-model-id` 作为默认，`RagSettings.rerankModelId` 可选库级覆盖。检索/重排调用时携带该模型 ID。模型 ID 属服务端配置，不作为密钥处理但也不在前端提供自由文本输入（只读展示当前生效值）。
- **验收标准**：
  1. 配置中心设置 `mis.kb.engine.rerank-model-id` 后，引擎配置页可只读查看当前生效的重排模型标识。
  2. **（L0-3，必验）** 检索期 `RetrieveQueryResolver` 在模型不可用时**不下发 `rerank_id`**；`RagflowClient.retrieve()` 请求体里该字段应**缺席**（而非空串 / `null` 字面量）。这是降级链路的第三道防线，与 WA-06 的 L0 前两条并立为 A2 发布门槛。
  3. **（L1，条件验，不阻塞发布）** 仅当测试环境**确实部署了重排模型**时执行：开启 rerank 后检索请求体带上正确 `rerank_id`，且返回顺序与关闭时存在可观测差异。环境无模型时，QA 报告须明确标注"待用户环境验收"，**不得**写成"已验证"，也不得含糊带过。
  4. 模型 ID 配置错误导致引擎报错时，问答链路返回友好业务提示（如"重排模型不可用，已按未重排结果返回"），**不向用户抛引擎原始错误栈**。
  - **验证诚实纪律（U2 裁决）**：L0 与 L1 在 QA 报告中必须**分段落断开陈述**，禁止用顿号把"已执行的验证"和"待用户环境验收"并列成一句话；主理人将逐条对照核验。

#### WA-06 · 无重排模型时禁用 rerank（A2）

- **描述**：当引擎不支持 rerank **或**未配置重排模型 ID 时，库设置页 rerank 开关置灰并说明原因；后端保存时强制 `rerank = false`（防绕过前端直调 API）。**U2 已裁决：本条按分级 L0/L1 验收（见下方验收标准）。**
- **验收标准（U2 裁决：分级 L0/L1）**：
  - **L0（必验，无条件阻塞发布）** —— 不依赖任何 rerank 模型即可跑通，是 A2 发布门槛：
    1. 未配置模型时，库设置页 rerank 开关**不可点击**（前端置灰），旁注具体原因（如"未配置重排模型，请联系平台运维"）。
    2. 直接调用设置接口传 `rerank = true` 时，后端落库结果为 `false`（或返回明确校验错误，二选一并写入接口文档）—— 第二道防线，防绕过前端。
  - **L0 合判**：以上两条 + WA-05 的 L0-3（检索期不下发 `rerank_id`）共同构成"降级链路可证"，**任一不过，A2 判不通过**。
  - **L1（条件验，不阻塞发布）** —— 仅当测试环境确实部署了重排模型时执行（见 WA-05 L1）；若环境无模型，本条 L1 不适用，QA 报告中标注"待用户环境验收"。

#### WA-07 · 命中测试后端接口（A4）

- **描述**：新增命中测试接口，链路为 `前端 → BFF /api/v1/kb/hit-test → mis-kb retrieve`，**只做召回、不调用 mis-rag / 不产生 LLM 消耗、不落问答会话表**。入参支持：库 ID（单库或多库，见待确认 Q4）、问题文本、临时覆盖的 `topK` / `similarityThreshold` / `retrievalMethod` / `vectorSimilarityWeight` / `rerank`。出参为 chunk 列表（文本、score、文档名、文档 ID、库 ID）。
- **验收标准**：
  1. 命中测试结果**必须经过 ACL 可见性过滤**：对当前用户不可见的库返回空或 403，不得出现越权片段（复用现有 `KbVisibilityService` 口径）。
  2. 临时覆盖参数**不落库**，不影响该库的持久化设置。
  3. 未传覆盖参数时，使用该库的持久化 RAG 设置（与 WA-02 同一合并逻辑）。
  4. 接口受独立权限码控制（建议 `kb:hittest:run`，最终取值见待确认 Q3）。
  5. **命中测试「调用」必须记审计**，复用 BFF 现有 `@OperLog` + `OperLogAspect` + `AuditWebClient` 机制。审计记录字段：**操作人 userId（明文，追责主体，不哈希）/ 库 ID / 问题（截断明文 ≤1000 字符，不脱敏）/ 结果条数 / 时间 / IP**。**不记 chunk 原文本身**（只记触发访问的问题词和命中条数，比例恰当）。理由：命中测试可读取跨库 chunk 原文，属内容访问行为，而本需求又明确禁止写 `kb_qa_*` 表——若不补审计，**这条内容访问路径将完全无痕**，对 internal/secret/confidential 密级库构成合规缺口。审计记录不进问答记录列表 A-02。
  6. **审计字段分层交付（2026-08-04 裁决，对齐架构 v1.1）**：① 基线层 = T12 仅加 `@OperLog`，访问事实（谁 / 何时 / 哪个端点 / 成功或越权被拒）100% 留痕、含失败路径（AOP finally 保证），零成本，作为合规地板；② 完整层 = T19（P1）增强切面 `recordParams` 属性，补 libraryId / 问题 / 结果条数三项。T19 以 `recordParams() default false` 设计，**存量端点零回归**。若发布窗口前公共模块变更被判风险过高，T12 基线保留、T19 转快速跟随，**不得因此阻塞 Wave A 发布**。

#### WA-08 · 命中测试前端页（A4）

**分区 A · 检索参数**

| 字段 | 控件 | 显隐 / 禁用逻辑 | 说明 |

## 9. 交付验收清单（对齐 phase2 规划 §9 Wave A）

- [ ] 文档与 UI 口径统一：hybrid = 关键字 + 语义，与 Graph 概念分离（WA-04 / WA-12）
- [ ] 库可配 `retrievalMethod` + `vectorSimilarityWeight`，且**参数真实作用于每次检索**（WA-01 / WA-02）
- [ ] `capabilities()` 含 `hybrid` / `rerank`；noop 降级行为有定义、有日志（WA-03）
- [ ] rerank 模型 ID 可配置；无模型时前后端一致地禁用（WA-05 / WA-06）
- [ ] 命中测试只 retrieve、可调参、经 ACL 过滤、不进问答记录，**且调用记审计（userId 明文 + 库 ID + 问题截断明文 ≤1000 字符 + 结果条数，不记 chunk 原文）**（WA-07 / WA-08）

- [ ] 空结果策略在问答侧的三种表现差异（WA-11 ②，P2 不阻塞；未完成则登记遗留，**不移交 Wave B**）
- [ ] 非目标核对：无 Neo4j、无图谱字段、无 RAPTOR、无浏览器持有引擎 Key
