### 1.1 原始需求复述

对 MIS 平台知识库的详细设置做改造，聚焦三件事：

1. **模型选择**：嵌入模型与重排模型均由「RAGFlow 服务器已配置的可选模型」探测拉取后下拉选择（不自建 MIS 模型配置表）；嵌入模型在创建知识库向导中选择，重排模型在知识库详细设置中选择。
2. **切片参数方案 B（库级默认 + 文件级覆盖）**：文档可单独指定切片方法 / token 数 / 分隔符，未指定则继承库级默认。
3. 配套的降级、来源回显、重解析引导等体验保障。

## 2. 产品定义

### 2.1 产品目标（三条正交）

1. **模型选择可控、不手输**：嵌入 / 重排模型选项全部来自 RAGFlow 模型池下拉，消除自由文本误配导致的建库/检索失败；嵌入模型建库后锁定，语义清晰。
2. **切片参数两级化**：库级默认 + 文件级覆盖，让表格、图片、长文等异构文档可用各自最优切片方式，且来源透明可追溯。
3. **降级可感知、不静默失效**：模型池不可达、重排模型不可用、切片参数来源等状态在 UI 明确呈现，配置了必须生效、失效必须告警并回退。

### 2.2 用户故事

> 按三类角色刻画，每条对应 §3 需求池编号。

#### 知识管理员（admin）

- **US-A1（R-P0-02）**：As a 知识管理员，I want 创建知识库时从模型池下拉选择嵌入模型（行内展示名称/维度/语言标签），so that 不会手输错模型名导致建库失败。
- **US-A2（R-P0-04）**：As a 知识管理员，I want 在库详细设置中从模型池选择重排模型（默认继承全局 `mis.kb.engine.rerank-model-id`），so that 不同库可用不同重排模型而无需改全局配置。
- **US-A3（R-P0-06/07）**：As a 知识管理员，I want 上传文档时为单个文档指定切片方式 / token 数 / 分隔符（未指定则继承库级），so that 表格/图片/长文各自用最优切片。

#### 运维（ops）

- **US-O1（R-P0-01）**：As a 运维，I want 模型池探测失败时界面明确提示并允许重试，so that 配置入口不卡死、不展示假选项。
- **US-O2（R-P0-05）**：As a 运维，I want 重排模型不可用时看到告警并自动回退全局默认，so that 检索不会因单个模型失效而整体失败。

#### 业务方（business）

- **US-B1（R-P0-08）**：As a 业务方，I want 在文档列表看到每个文档的切片方式与来源（继承库级/文件指定），so that 我能理解检索效果差异的原因。
- **US-B2（R-P0-08）**：As a 业务方，I want 修改文件级切片参数后明确看到该文档将重新解析、解析期间暂不参与检索，so that 不会误以为新参数立即生效。

| **R-P0-06** | **切片文件级方案 B（数据模型）**：`kb_document` 新增切片覆盖字段（`chunk_method` / `chunk_token_num` / `separator`，均可空 = 继承库级）；Flyway V23 建列。**必须**与库级 `RagSettings` 切片字段语义对齐（方法码值、token 正整数、分隔符允许纯空白）。 | V23 迁移可重复执行；三列均可空；存量文档三列为 NULL 且读取行为与现状一致（继承库级）。 |

## 5. 非功能需求

1. **模型池探测的缓存与降级**：
   - 探测结果**必须**缓存（建议 JVM 级短 TTL，如 60s，随引擎健康刷新失效），避免每个页面/每次下拉都打 RAGFlow。
   - RAGFlow 不可达/探测失败时：嵌入模型下拉回落自由文本输入（带「模型池不可用」告警 + 重试按钮）；重排模型下拉回落「仅全局默认」或禁用并沿用现有 rerankSupported=false 置灰。**绝不允许**展示假选项或把错误当空列表。
2. **下拉选项与引擎能力的联动**：重排模型下拉仅在 `capabilities.rerankSupported === true` 时可操作（复用现有 `=== true` fail-safe 判定，能力未确认即灰化，QA P2-A 口径）。
3. **两级切片合并的展示语义**：文档行来源回显基于「文件级字段是否非空」判定（任一非空 = 文件指定；全空 = 继承库级）；实际生效值 = 文件级字段 ?? 库级字段 ?? 全局默认，语义对管理员透明。
4. **兼容与安全**：存量自由文本 embeddingModel 值只读展示、不回写不迁移；模型列表接口不暴露 RAGFlow 密钥；模型池相关接口复用现有 KB 管理权限。
5. **性能**：模型列表接口应轻量（模型数量级为个位数~十位），下拉渲染无感知延迟；文档列表新增列不引入额外引擎调用（切片字段来自本地 `kb_document`）。

## 6. 待确认问题（≤3，均给默认建议）

> 已拍板项（模型池来源 = RAGFlow 探测、切片 = 方案 B）不再列为开放问题。

1. **RAGFlow 模型池探测接口的具体路径与分类方式**：不同 RAGFlow 版本的模型列表 API（路径/字段）有差异，Embedding 与 Rerank 如何按类型归类需实测确认。
   - **默认建议**：接入 RAGFlow 模型列表接口（如 `/api/v1/llm/list` 或等价），按类型字段（embedding/rerank）分类；接口不可用时整体降级（§5.1），由架构师在技术设计中固化在 RagflowClient 并给出实测结论。
2. **嵌入模型「留空」语义是否保留**：现状是自由文本留空 = 引擎默认。
   - **默认建议**：保留「引擎默认（留空）」选项作为下拉首项；选中具体模型才提示锁定。
3. **文件级切片参数下发 RAGFlow 的机制**：上传文档接口是否支持单文档级 `chunk_method`/`parser_config` 覆盖取决于 RAGFlow 版本。
   - **默认建议**：优先上传接口带参；若版本不支持，则由 MIS 落库（R-P0-06 字段）并在触发解析时带参下发，架构师需在技术设计中确认版本能力并选择其一。

## 7. 交付边界说明

- 本期**不实现**：嵌入模型更换（重建库）流程（P1）、单次问答覆盖重排模型（P1）、模型池管理后台（P2）、跨模型对比（P2）、使用统计（P2）。
- 本期**保持现状**：参数层级「全局默认 → 库设置 → 单次问答覆盖」由 `RetrieveQueryResolver` 三级合并的机制不动；重排模型库级值加入合并链时，沿用既有「库设置覆盖全局」语义，且**不得**绕过 Resolver 内联判断（设计文档 §7.2 铁律）。
